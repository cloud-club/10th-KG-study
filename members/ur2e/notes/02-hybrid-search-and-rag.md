# 하이브리드 검색과 작업기록 RAG

## 목표

2주차에는 같은 작업기록을 grep, Elasticsearch BM25, pgvector로 각각 검색했다. 이번에는
BM25와 벡터 검색의 후보 순위를 RRF로 결합하고, 최종 청크를 근거로만 답하는 챗봇을 만든다.

```text
질문
 ├─ BM25: 정확한 기술 용어와 명령어에 강함
 └─ Vector: 표현이 달라도 의미가 가까운 문서에 강함
          ↓
       RRF 순위 결합
          ↓
    상위 근거 청크 [C1..C5]
          ↓
       LLM 답변 + 인용
```

## RRF를 선택한 이유

BM25 점수와 코사인 유사도는 범위와 의미가 달라 원점수를 바로 더할 수 없다. RRF는 원래 점수를
버리고 각 검색의 순위만 사용한다.

```text
RRF(d) = Σ 1 / (k + rank(d))
```

현재 기본값은 `k=60`, 각 검색의 후보는 20개다. 같은 청크가 두 검색에서 모두 높은 순위에
등장하면 두 항이 더해져 최종 순위가 올라간다. UI에는 최종 RRF 점수뿐 아니라 BM25·Vector의
원래 순위도 같이 표시해 결과가 왜 올라왔는지 확인한다.

## 비교 방법

2주차 평가 질문 19개를 그대로 사용하여 다음을 비교한다.

- BM25
- Vector
- Hybrid RRF
- 지표: Hit@3, MRR
- 청킹: heading / fixed-size + overlap

검색 방식과 청킹을 동시에 바꾸면 원인을 구분하기 어려우므로, 한 번의 비교에서는 같은 청크 집합과
같은 평가 질문을 사용한다.

## 근거형 챗봇

검색된 청크에는 `[C1]`, `[C2]`처럼 안정적인 번호를 붙인다. LLM은 제공된 근거만 사용하고 모든
사실 주장에 해당 번호를 붙인다. 존재하지 않는 번호를 인용하면 애플리케이션이 오류로 처리한다.

## 4주차로 넘길 실패 질문

하이브리드 검색도 질문과 비슷한 청크를 찾는 방식이라, 여러 문서에 흩어진 관계를 차례로 따라가야
하는 질문에는 한계가 있다.

- 인증서 만료 장애의 원인, 조치, 검증, 미완료 후속 작업을 한 번에 묻는 질문
- Harbor와 Nexus를 분리한 결정과 관련 장애를 함께 묻는 질문
- 같은 원인을 가진 장애를 모아 해결 방법을 비교하는 질문

이 질문들은 4주차 작업기록 지식 그래프의 평가 질문으로 사용한다.
