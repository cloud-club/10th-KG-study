> RAG 평가는 검색·생성 두 층으로 끝나지 않는다. sese2204가 **대화 층**(턴별 faithfulness, 지시대명사 해소, non-standalone 질문)과 **시스템 층**(p50/p99, 토큰 비용, 거부율, 안전성)을 더해 네 층으로 정리했고, 거기에 직교하는 두 축 — 어떤 **기준**(reference)으로 재는가 다섯 가지, **누가** 채점하는가 네 가지 — 를 붙였다. 핵심 함정: reference-free 지표는 "정답과 맞나"가 아니라 "주어진 근거와 모순 없나"를 재므로 **근거가 틀리면 만점**이다. 멤버 실측과 골든셋 절차는 [[RAG-평가-지표]], 도구는 [[RAGAS]].

## 네 층위 (sese2204)

| 층 | 지표 | 기준 데이터 |
|---|---|---|
| ① 검색 | recall@k, precision@k, NDCG@k, MRR, context precision/recall | 질문별 정답 청크 ID |
| ② 생성 | faithfulness, answer relevancy, answer correctness | 근거 문서 또는 정답 문장 |
| ③ **대화** | 턴별 faithfulness, 지시대명사 해소 정확도, 무응답 처리율, topic adherence | 대화 로그 + 턴별 정답 |
| ④ **시스템** | p50/p99 지연, 토큰 비용, 거부율, 안전성 위반율, 사용자 만족 | 로그·가드레일 |

- 07번 노트의 "검색 vs 생성 실패"가 ①②이고 ③④가 신규다. Yeongeunn 04도 적재(ID·해시·건수) / 검색 / 생성(수작업) / 시스템의 4층을 독립적으로 세웠다.
- **RGB의 RAG 4능력**: Noise robustness / **Negative rejection** / Information integration / Counterfactual robustness. 논문 결론 — 노이즈는 어느 정도 되지만 거부·통합·반사실 셋은 크게 취약. "검색이 좋아지면 답도 좋아진다"가 깨지는 구간이 있다.
- **MTRAG**: 사람이 만든 110개 대화, 평균 7.7턴, 842 태스크, 4도메인. 강제 조건 셋 — 후반 턴 열화 / **non-standalone 질문**("그럼 그건 언제야?") / unanswerable. 검색은 nDCG@5, 생성은 품질·근거 충실도의 조화평균으로 분리. **단일 질문만 만들면 ③층을 아예 못 잰다** → 3~5턴 시나리오를 넣는다.
- **RAGChecker**: 점수가 아니라 **진단**. claim 단위 entailment를 검색기(claim recall, context precision)와 생성기(context utilization, noise sensitivity, hallucination, self-knowledge, faithfulness) 지표로 분해 — "점수가 낮다"에서 "리랭커가 노이즈를 못 걸러 생성기가 휘둘렸다"까지 내려간다.

## 기준 다섯 가지 (만들기 쉬운 순)

없음(reference-free) → 정답 근거 → 정답 문장 → 루브릭 → 선호 쌍(Elo / Bradley-Terry). **reference-free는 "정답과 맞나"가 아니라 "근거와 모순 없나"를 잰다 — 근거가 틀리면 만점.** 그래서 검색 층은 반드시 reference contexts로 따로 잰다. [[RAGAS]] 카탈로그의 절반 이상이 `reference`를 요구한다.

## 심판 네 가지

| 심판 | 비용 | 함정 |
|---|---|---|
| 규칙·문자열 | 공짜 | 표현이 다르면 0점 |
| 임베딩 | 저렴 | **부정문을 못 잡는다** |
| 사람 | 비쌈 | **사람끼리도 약 80%만 일치** |
| LLM-as-judge | 중간 | 80%+ 일치(사람끼리 수준), 편향·비결정성 |

- 근거: Zheng et al.이 MT-Bench(80문항 멀티턴, 8카테고리)·Chatbot Arena(투표 3만 건)로 검증 — GPT-4 심판과 사람 일치율 80% 초과 = 사람끼리의 일치율 수준.
- **편향 3종과 보정**: Position(먼저 제시된 답 선호 → 순서 바꿔 2회, 불일치 시 무승부) / Verbosity(긴 답 → 길이 페널티, single-answer grading) / Self-enhancement(자기 계열 선호 → 다른 계열·복수 심판). 추가: 프롬프트 형식 편향, 캘리브레이션 드리프트, 자기 출력 인식력과 자기선호 강도의 선형 상관(Panickssery 2024).
- **실무 규칙 5**: 심판 모델·프롬프트·온도 고정 + 버전 기록 / 쌍대는 양방향 / 절대 점수보다 **동일 골든셋의 상대 변화** / 골든셋 50~100개는 사람이 채점해 일치율 선확인 / 심판에게 근거 먼저(CoT) 쓰게 한 뒤 점수. Yeongeunn 08: "LLM 평가자를 쓰더라도 평가자 모델·프롬프트를 고정하고 일부는 사람이 교차 검토", 모델 비교는 "모델 이름을 가리고 사람이 채점".
- **오프라인 → 온라인 루프**: 프로덕션 실패를 골든셋에 환류. "골든셋은 정적이 아니라 자란다."

## 멤버들이 확인한 것

- 실측은 없다 — sese2204·Yeongeunn 둘 다 문헌 정리이고 수치는 논문 보고값이다. 멤버 실측과 맞물리는 지점 둘:
  - lys0611의 TODO "정답 라벨을 두 사람이 붙였을 때 일치도" ← 기준선 "사람끼리 80%". lys0611의 "인용 P/R을 NLI로 근사" ← RAGChecker의 claim 단위 entailment가 바로 그 접근.
  - e0ng은 LLM-as-a-Judge(0~3점)로 36문항 골든셋을 만들었고, LLM이 후보를 직접 고를 때의 편향을 자인해 pooling으로 바꿨다. kdyann은 **검토자 LLM**을 답변 루프에 넣어 과잉 거절을 겪었다 → [[RAG-루프와-근거-인용]].
- 공개 벤치마크 (Yeongeunn 08 정리): MMLU(2020-09, 57분야 객관식), TruthfulQA(2021-09), HELM(2022-11, "단일 평가셋이 아니라 평가 프레임워크"), Ragas(2023-09). "버전·분할·프롬프트·few-shot 수·채점 방식을 함께 적어야 한다. 학습 중 공개 문제를 접했을 가능성."

## 열린 질문

- 스터디 평가셋은 전부 단일 질문이다. ③층(멀티턴·non-standalone)을 잰 멤버는 없다.
- 거절(negative rejection)을 재는 지표가 RAGAS에 없고 오히려 감점된다. lys0611의 거절 성공률이 유일한 실측 → [[RAGAS]].
