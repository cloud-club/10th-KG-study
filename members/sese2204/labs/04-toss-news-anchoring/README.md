# 04. 시세에 기사를 붙인다 — 토스증권 방식 재현

> 보고서: [report.html](report.html) (브라우저로 열면 차트를 눌러 볼 수 있음)
> 가상 종목·가상 기사이며 실존 기업과 무관하다. 토스 사례는 엔지니어와 나눈 비공식 대화가 출발점이고, 구현 세부는 확인되지 않았다.

## 목표

토스증권은 뉴스로 주가를 예측하지 않는다고 한다. 주가가 움직인 구간을 먼저 잡고, 그 시간대의 기사를 붙인다. 이 방식을 가상 종목 6개와 가상 기사로 재현했다. 기사마다 "어느 움직임의 이유인지" 정답을 심어 두어서, 결과를 정답과 바로 대조할 수 있다.

핵심 질문은 **기준점(앵커)을 먼저 세우고 거기에 텍스트를 붙이는 구조가 작동하는가**, 그리고 **같은 시간대에 나왔다는 것만으로는 왜 부족한가**이다.

## 처리 순서

앞 단계의 출력이 다음 단계의 입력이다.

1. **움직임(앵커)을 잡는다.** 직전 60봉의 중앙값과 중앙절대편차(MAD)로 잰 z가 3.5 이상인 봉을 이어 붙이고, 누적 2% 미만은 버린다.
2. **기사를 종목에 잇는다.** 연결 강도는 네 가지다.
   - 명시: 종목코드가 있음
   - 엔티티: 사명이나 별칭 사전에 걸림
   - 모호: "한빛"처럼 두 종목에 걸림
   - 섹터(약함): 업종어만 있음
3. **시간 창으로 역할을 정한다.** 기사가 움직임 60분 전부터 10분 후 사이에 있으면 이유 후보로 둔다. "[특징주] 급등" 같은 기사는 시황 기사로, 몇 시간 뒤 나온 "왜 올랐나"는 사후 해설로 따로 센다.
4. **재료성을 거른다.** 임원 인사, 공채, ESG처럼 주가와 무관한 기사는 점수를 낮춘다. 토스가 공개한 "뉴스 분류"에 해당하는 자리인데, 여기서는 사전으로 대신했다.
5. **접어서 한 줄로 쓴다.** 제목이 겹치는 기사를 신호 하나로 묶는다. 점수가 기준에 못 미치면 "이유 미상"이라고 쓰고, 원인이라고 단정하지 않는다.

## 결과

가상 시세는 20거래일, 10분 봉(하루 39봉)이다.

seed 7 한 번:

| 항목 | 값 |
|---|---|
| 기사 / 심은 움직임 / 잡은 앵커 | 486 / 25 / 22 |
| 앵커 정밀도 / 재현율 | 1.00 / 0.88 |
| 이유 있는 움직임: 1순위 신호가 정답 | 17 (오답 0, 못 붙임 0) |
| 이유 없는 움직임: "미상"으로 둠 | 5 (엉뚱한 기사 붙임 0) |
| 원인 기사 → 신호로 접힘 | 60건 → 17개 |

seed 10개 합산, 기본형과 개선형 비교:

| 지표 | 기본형 (`--baseline`) | + 2% 하한·재료성 |
|---|---|---|
| 앵커 정밀도 | 0.737 | 1.000 |
| 앵커 재현율 | 0.936 | 0.936 |
| 부착 기사 정밀도 | 0.885 | 1.000 |
| 1순위 신호 정답 / 오답 / 못 붙임 | 165 / 11 / 1 | 174 / 0 / 2 |
| 이유 없는 움직임: 미상 정답 / 엉뚱한 기사 | 45 / 14 | 58 / 0 |
| 대조군: 기사가 나온 뒤 60분 안에 움직임이 온 비율 | 0.127 | 0.119 |

- **같은 시간대의 기사가 이유는 아니다.** 4단계(재료성)와 2% 하한을 빼면, 기사 없이 움직인 구간에 우연히 같은 시간대에 나온 배경 기사(임원 인사, 공채 공고)가 붙는다. 기본형의 "엉뚱한 기사 붙임" 14건이 이것이다.
- **방향을 바꾸면 문제가 바뀐다.** 기사를 보고 움직임을 예측하는 쪽은 기사 뒤 60분 안에 실제로 움직임이 온 비율이 약 12%라서 열에 아홉이 빗나간다. 움직임에 기사를 붙이는 쪽은 예측이 아니라 검색·분류 문제가 된다.

## 한계

- **수치는 구조가 작동한다는 증거일 뿐이다.** 1.00이 나온 것은 기사를 만든 어휘와 판정 사전을 같은 사람이 썼기 때문이다. 정확도의 근거로 쓰면 안 된다.
- **실제로 어려운 곳은 가상 데이터가 비워 둔 세 군데다.** 재료성 분류(LLM이 맡을 몫), 별칭 해소, 이유 없이 움직인 구간에 걸리는 배경 기사.
- 재현 스크립트 `toss_repro.py`(`python3 toss_repro.py --seed 7`, 기본형은 `--baseline`)는 이 폴더에 없다. 보고서 HTML에는 그 결과 데이터만 들어 있다.

## 지식그래프와의 연결

앵커를 먼저 정하고 텍스트를 시간 창과 엔티티로 붙이는 구조는, 대화·문서에서 트리플을 뽑을 때도 그대로 나타난다. 같은 창 안에 있다는 것만으로는 관계가 되지 않는다. 별칭 해소도 이 보고서가 꼽은 어려운 곳 가운데 하나인데, 지식그래프에서 사람·기관 노드가 별명마다 따로 생기는 문제와 같다.
