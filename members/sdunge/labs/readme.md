# 02-law-search: 형사 판례 검색 실습 (grep → BM25 → RAG 에이전트)

법제처 OPEN API로 형사 판례를 수집하고, 검색의 세 세대(grep / BM25 / RAG)를 직접 구현하며 각 방식의 장단점을 비교한 실습.

## 개요

| 항목 | 내용 |
|------|------|
| 데이터 출처 | 법제처 국가법령정보 공동활용 OPEN API (판례 목록·본문 조회) |
| 대상 | 형사 판례 (검색어 "사기", 2020~2024 선고) |
| 수집량 | 본문 포함 형사 판례 73건 → 청크 2,443개 |
| 검색 엔진 | Elasticsearch 9.1.0 (BM25) |
| LLM | Claude (Anthropic API) |

## 데이터 수집

법제처 API는 **목록 조회 → 본문 조회** 2단계로 동작한다.

1. `lawSearch.do` (목록조회): 검색어로 판례 목록과 `판례일련번호`를 받음
2. `lawService.do` (본문조회): 일련번호로 판결 전문(판시사항, 판결요지, 참조조문, 참조판례, 판례내용)을 받음

**주의 — 출처에 따라 본문이 없음:** 검색어 "사기"로 목록을 받으면 `국세법령정보시스템` 출처의 행정 판례가 섞여 들어오며, 이들은 본문 조회 시 "일치하는 판례가 없습니다"를 반환한다. `search=2`(판시내용까지 검색) + 선고일자 범위를 지정해 일반 법원의 형사 판례만 걸러 본문을 확보했다.

## 데이터 저장 구조

### Elasticsearch 인덱스 `prec_chunks`

판례 본문을 청킹하여 청크 하나를 문서 하나로 저장한다.

| 필드 | 타입 | 용도 |
|------|------|------|
| chunk_id | keyword | 청크 고유 ID (`판례일련번호_인덱스`) |
| 판례일련번호 | keyword | 원본 판례 ID |
| 사건명 | keyword | 판례 제목 |
| content | text | BM25 검색 대상 본문 |
| char_count | integer | 청크 글자 수 |

### 청킹 전략

| 파라미터 | 값 | 의미 |
|----------|-----|------|
| chunk_size | 500 | 청크 하나당 글자 수 |
| overlap | 100 | 청크 간 겹치는 글자 수 (경계에서 문맥 유지) |

→ 판례 73건이 청크 2,443개로 분할됨 (평균 약 33청크/판례)

## 검색 3세대 비교

같은 검색어를 세 방식으로 검색한 결과. 세 단어는 모두 "속이다"라는 같은 의미를 가진다.

| 검색어 | grep (0세대, 글자 매칭) | BM25 제목 (1세대) | BM25 본문 청크 (1세대) |
|--------|------------------------|-------------------|----------------------|
| 사기 | 384줄 | 149건 | 189청크 |
| 기망 | 3줄 | — | 10청크 |
| 속여 | **0줄** | — | **9청크** |

### 발견한 것

- **grep의 한계 (표현 불일치):** "사기"는 384줄을 찾지만, 같은 뜻인 "기망"은 3줄, "속여"는 **0줄**. grep은 글자만 매칭하므로 표현이 다르면 의미가 같아도 못 찾는다.
- **grep의 한계 (순위 없음):** 매칭된 줄에 중요도 순위가 없다.
- **청킹 + 본문 검색의 효과:** 제목만이 아니라 본문을 청킹해 색인하니, grep에서 0건이던 "속여"가 본문 청크에서 9건 잡혔고 관련도 점수(7.80)까지 매겨졌다. 본문에는 "속여서", "가장하였으며" 등 실제 표현이 들어 있기 때문이다.

## RAG 에이전트 (개인 데이터 에이전트 v1)

```
질문 → BM25 본문 검색 → 검색된 판례를 컨텍스트로 조립 → Claude가 근거와 함께 답변
```

**예시 질문:** "보이스피싱 판례의 특징이 뭐야?"

→ 검색된 판례 본문을 근거로, 조직적 역할 분담(현금수거책·전달책), 사기 수법(대환대출 사칭, 위조 사문서 활용) 등을 실제 판례 내용을 인용하며 답변. 검색 결과에 없는 내용은 지어내지 않도록 프롬프트로 제약.

## 실행 방법

```bash
# 1. 공용 인프라 실행 (저장소 루트에서)
docker compose up -d

# 2. 패키지 설치
pip3 install requests pandas elasticsearch anthropic --break-system-packages

# 3. 노트북 실행 (law_data.ipynb)
#    - 판례 목록/본문 수집 → CSV 저장 (data/raw/)
#    - 청킹 → data/processed/chunks.csv
#    - Elasticsearch 색인 → BM25 검색
#    - Claude API로 RAG 에이전트
```

`.env`에 `Claude_API_KEY`를 설정해야 에이전트가 동작한다. (`.gitignore`로 제외)

## 남은 과제 (다음 단계)

- **pgvector (2세대 벡터 검색):** 임베딩 모델(`jhgan/ko-sroberta-multitask`, 768차원)로 청크를 벡터화해 의미 기반 검색 구현. (현재 `psycopg` 드라이버 이슈로 보류)
- **하이브리드 검색:** BM25 + 벡터 결과를 RRF로 융합
- **에이전트가 못 답하는 질문 수집:** 비교·집계·다중조건 질문(예: "보이스피싱과 일반 사기의 형량 차이")은 단일 검색으로 부정확 → 하이브리드·에이전틱 검색의 필요성으로 연결
- **참조판례·참조조문 활용:** 본문에 포함된 참조 관계를 지식그래프의 엣지로 구축
