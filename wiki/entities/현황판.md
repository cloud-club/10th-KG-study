> `members/`를 스캔해 누가 무엇을 얼마나 했는지 보여주는 GitHub Pages 정적 사이트. 위키가 "무엇을 알게 됐나"를 맡는다면 현황판은 "누가 어디까지 왔나"를 맡는다. 주소 https://cloud-club.github.io/10th-KG-study/

## 기준 · 루틴

- `main`에 푸시될 때와 매일 09:00 KST(cron `0 0 * * *`)에 GitHub Actions `deploy-dashboard`가 `scripts/build_dashboard.py`를 돌려 `dashboard/data.json`을 만들고 Pages로 배포한다. 히트맵·연속 출석일은 하루 한 번은 갱신된다.
- 입력은 `members/<id>/`의 `README.md`(소개), `readings.md`(주차별 읽을거리), `notes/*.md`, `labs/*/README.md`와 git 히스토리. 노트 맨 위 frontmatter(`title`·`date`·`tags`·`status`)를 읽고, `tags`가 지식그래프의 주제 노드가 된다. 태그가 비면 GPT가 본문을 읽고 채운다.
- LLM(OpenAI, 기본 `gpt-5-mini`, 레포 Secret `OPENAI_API_KEY`)이 멤버별 칭호·요약·태그, 스터디 소식(digest), 커밋 중계("중계석")를 만든다. 키가 없으면 규칙 기반 폴백으로 빌드된다. 결과는 `.cache/llm-cache.json`에 프롬프트 해시로 캐시되어 Actions cache로 이어진다.
- 중계석 도배 방지: 같은 멤버가 같은 날 올린 커밋은 한 사건으로 묶고, 한 멤버는 피드에서 커밋 사건을 최대 3개까지만 차지한다. `dashboard/`·`scripts/`·`templates/`·`wiki/`·`.claude/`·`CLAUDE.md`·README·CONTRIBUTING만 바꾼 커밋은 인프라 커밋으로 분류해 피드에서 뺀다.
- 이름 표시는 `members/names.json`(id → 이름), 반 구분은 `members/cohorts.json`(반별 명단). 명단에 없는 멤버는 "다음 반"에 자동으로 들어간다.

## 절차

1. 로컬 미리보기: `python3 scripts/build_dashboard.py` (LLM 없이) 또는 `OPENAI_API_KEY=… python3 scripts/build_dashboard.py`, 그다음 `python3 -m http.server -d dashboard 8000`.
2. 스캐너 로직을 바꾸면 `python3 -m unittest discover -s scripts -p "test_*.py"`가 통과해야 한다. Actions도 배포 전에 같은 테스트를 돌린다.
3. 새 멤버가 폴더를 만들면 `members/names.json`에 이름을, `members/cohorts.json`에 반을 넣는다.

## 겪은 문제 · 배운 것

- 스캐너는 `notes/*.md`와 `labs/*/README.md`만 읽는다. `members/sunghyun/note/`(단수)와 `members/dldusgh318/notes/week2/`, `labs/01-three-generations/WEEK3_*.md`처럼 규칙 밖 경로의 문서는 현황판에 잡히지 않는다. 위키 ingest는 이런 소재도 읽으므로 [[스터디-노트-지도]]에 표시해 둔다 (2026-09-16 린트).
- `members/names.json`에 `do-dop`·`ur2e`가 없다(2026-09-16 기준). 현황판에는 아이디로 표시된다.
- 커밋 작성자를 멤버에 연결하는 순서는 멤버 폴더 경로 → GitHub 로그인(`GITHUB_TOKEN`으로 조회, 캐시) → 이메일이다. `shared/` 커밋도 히트맵과 최근 활동에 포함된다.
