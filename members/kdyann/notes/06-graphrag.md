# 06. GraphRAG — 검색과 그래프의 결합

> 그래프를 RAG의 검색과 컨텍스트 구성에 어떻게 활용할까?

## GraphRAG 패턴 3종

| 패턴 | 흐름 | 특징 |
| --- | --- | --- |
| 로컬 서치 | 질문의 엔티티를 그래프 노드에 연결 → 주변 서브그래프 탐색 → 관련 근거를 컨텍스트로 구성 | 특정 대상과 그 관계를 묻는 질문에 사용 |
| 글로벌 서치 | 그래프의 커뮤니티 탐지 → 커뮤니티별 요약 → 여러 요약을 종합 | 그래프 전반의 주제나 흐름을 묻는 질문에 사용 |
| Text2Cypher | 질문을 바탕으로 LLM이 Cypher 질의를 생성 → 그래프 조회 | 정해진 그래프 스키마에서 조건·관계를 질의할 때 사용 |

- 로컬 서치는 질문에서 찾은 노드 주변의 좁은 범위를 읽는다. 
- 글로벌 서치는 미리 만든 커뮤니티 요약을 모아 넓은 범위를 읽는다.
- Text2Cypher는 자연어 질문을 그래프 질의로 바꾸는 방식이다.

## 하이브리드 리트리버

```text
질문 → 벡터 검색으로 관련 진입 노드 찾기 → 그래프 관계를 따라 확장 → 원문 근거와 함께 컨텍스트 구성
```

벡터 검색은 질문과 의미가 비슷한 시작점을 찾고, 그래프 탐색은 그 시작점에 연결된 노드와 관계를 찾는다. 확장된 경로가 답의 근거가 되는지는 연결된 원문과 함께 확인해야 한다.

## 그래프 인덱싱: 빌드 시점 선지불

글로벌 서치에 쓸 커뮤니티 탐지와 커뮤니티 요약은 질문이 들어올 때마다 처음부터 만들기보다 **미리 배치 작업으로 생성**할 수 있다. 그래프를 구축할 때 계산·요약 비용을 먼저 내고, 질의 시점에는 저장된 요약을 검색하고 종합하는 방식이다. 데이터가 바뀌면 영향을 받은 그래프와 요약을 갱신해야 한다.

## 회사에서는 어떻게 활용할까? — 토스증권 사례

GraphRAG의 검색 방식을 공부하다가 실제 회사에서는 관계를 찾는 검색을 어떻게 만드는지 궁금해 [토스증권 기술 블로그](https://toss.tech/article/tech_talk_talk_3)를 읽었다. 이 글은 회사·종목·제품·이벤트·테마를 연결한 금융 지식그래프에서, 질문과 관련된 서브그래프를 찾아 반환하는 검색기에 초점을 맞춘다.

1. 질문과 관련된 시작 엔티티 후보를 Elasticsearch 기반 검색 파이프라인으로 찾는다.
2. 시작점에서 관계를 따라 경로를 확장한다. 무작정 확장하면 3홉에서 후보 경로가 약 4,924만 개까지 늘어나므로, 홉마다 점수를 매기고 상위 후보만 다음 홉으로 넘긴다.
3. 질문 관련성에 더해 시가총액·최신성 같은 금융 신호와 제품별 `path_preference`를 반영해 남길 경로를 고른다.

글을 읽고 로컬 서치에서 어디서 시작하고 어떤 경로를 남길지가 중요하다는 것을 알게 됐다.

그래프에 관계를 많이 담고 더 멀리 탐색하면 다양한 답을 찾을 수 있을 것 같지만, 토스증권 사례에서는 3홉만 가도 후보 경로가 크게 늘어났다. 그래프를 활용하려면 연결을 만드는 것만큼 질문과 무관한 경로를 일찍 줄이는 기준이 필요하다는 점이 인상적이었다.

내 콘텐츠 그래프에도 `내 게시물 → 주제 ← 참고 게시물` 경로가 있다. 같은 주제로 연결됐다는 사실은 확인할 수 있지만, 그 참고 글이 내 계정에 어울리는지까지 자동으로 증명하지는 않는다. 지금도 원문 근거·최근성·관심 분야를 확인하지만, 좋은 추천을 위해서는 여러 후보 중 어떤 경로를 우선할지 더 고민해야 한다.

앞으로는 같은 질문을 기존 하이브리드 검색과 그래프를 결합한 검색에 각각 던져 보고 싶다. 단순히 비슷한 글을 찾는 질문과 여러 게시물의 관계를 따라야 하는 질문을 나눠서, 어느 쪽이 필요한 근거를 더 잘 찾는지 비교해 보면 GraphRAG가 필요한 상황을 더 분명히 이해할 수 있을 것 같다.
