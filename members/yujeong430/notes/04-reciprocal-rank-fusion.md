# RRF - 순위로 검색 결과를 융합하는 방법

## 한 줄 요약

RRF(Reciprocal Rank Fusion)는 여러 검색기의 **점수 자체를 더하지 않고**, 각 검색 결과에서의 **순위**만 이용해 하나의 순위를 만드는 방법이다.

## 왜 결과를 합쳐야 하는가

같은 질문이라도 키워드 검색과 벡터 검색은 서로 다른 장점을 가진다.

- 키워드 검색은 정확한 명칭·날짜·코드처럼 **표현이 정확히 겹치는 정보**에 강하다.
- 벡터 검색은 질문과 문서의 표현이 달라도 **의미가 비슷한 정보**를 찾는 데 강하다.

둘이 가져온 상위 문서 목록을 하나로 합치면, 한 방식이 놓친 문서를 다른 방식이 보완할 수 있다. 이를 결과 융합(result fusion)이라고 한다.

## 점수를 바로 더하면 왜 어려운가

BM25 점수와 코사인 유사도는 숫자로 보이지만 같은 척도가 아니다.

```text
BM25 결과:       A = 12.4, B = 8.1
벡터 검색 결과:  A = 0.62, C = 0.91
```

`12.4`가 `0.91`보다 더 관련 있다는 뜻은 아니다. 두 점수는 계산 방식, 데이터 분포, 질의 길이가 모두 다르기 때문이다. 따라서 단순히 더하면 한 검색기의 숫자 범위가 결과를 지배할 수 있다. 점수 정규화는 이를 맞추려는 방법이지만, 어떤 정규화가 적절한지 별도 검증이 필요하다.

RRF는 이 문제를 피한다. “점수가 얼마인가” 대신 “각 검색기에서 몇 등인가”만 본다.

## 계산 방법

문서 `d`의 RRF 점수는 다음과 같다.

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

- `rank_i(d)`: 검색기 `i`의 결과에서 문서 `d`의 순위. 1위부터 시작한다.
- `k`: 순위 상수(rank constant). 낮은 순위의 영향이 너무 커지지 않도록 완화한다.
- 어떤 검색기 결과에 문서가 없으면, 그 검색기는 해당 문서에 점수를 더하지 않는다.

예를 들어 `k = 60`이고 문서 A가 BM25 1위, 벡터 검색 3위라면:

```text
RRF(A) = 1 / (60 + 1) + 1 / (60 + 3)
```

문서 B가 BM25에서만 1위라면 `1 / 61`만 받는다. 즉, 두 검색기 모두에서 상위에 나온 문서는 더 높은 최종 순위를 얻는 경향이 있다.

## 직관

```text
BM25 순위:   A(1위)  B(2위)  C(3위)
벡터 순위:   D(1위)  A(2위)  C(3위)

RRF 결과:    A와 C는 두 목록에 모두 있으므로 점수가 누적됨
```

RRF는 “두 방식이 독립적으로도 상위라고 판단한 문서”를 신뢰하는 간단한 합의 방식이다. 단, 한 검색기에만 있는 좋은 문서를 자동으로 제거하는 방식은 아니다. 그 문서도 해당 검색기에서 받은 순위 점수는 유지한다.

## `k`가 하는 일

`k`가 작으면 1위와 10위의 차이가 더 크게 반영된다. `k`가 크면 하위 순위도 비교적 고르게 반영된다. Elasticsearch RRF의 기본 `rank_constant`는 60이다. 이것은 정답값이 아니라, 데이터와 검색기 조합에 따라 평가로 조정할 수 있는 값이다.

## RRF가 해결하지 않는 것

- 두 검색기가 모두 관련 문서를 가져오지 못하면 RRF도 만들 수 없다.
- 순위만 보므로 “1위와 2위 점수 차이가 매우 큰 상황”이라는 정보는 버린다.
- 문서 내용의 사실성이나 답변의 정확성을 보장하지 않는다. RRF는 **검색 결과 순위화** 단계의 방법이다.
