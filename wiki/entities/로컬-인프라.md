> 실습용 DB 세 개(PostgreSQL 17 + pgvector, Elasticsearch 9 + nori, Neo4j 5.26 + APOC)를 `docker compose up -d` 한 번에 띄우는 공용 환경. 사용법의 원본은 `infra/README.md`이고, 이 페이지는 거기서 겪은 함정과 판단, 그리고 공용을 안 쓴 멤버들의 구성을 모은다.

## 기준 · 루틴

| 서비스 | 이미지 | 접속 | 용도 |
|---|---|---|---|
| PostgreSQL 17 + pgvector | `pgvector/pgvector:pg17` | `postgresql://kg:kg@localhost:5432/kg` | 청크·메타데이터·임베딩 저장, 벡터 검색, pg_trgm |
| Elasticsearch 9 + nori | `infra/elasticsearch/Dockerfile` | `http://localhost:9200` (인증 없음) | BM25 / 하이브리드, 한국어 형태소 |
| Neo4j 5.26 LTS + APOC | `neo4j:5.26-community` | `bolt://localhost:7687`, Browser 7474 (neo4j / kgstudy2026) | 지식그래프 |
| Kibana (선택) | `kibana:9.1.0`, `--profile ui` | `http://localhost:5601` | ES 인덱스 탐색 |

- `cp .env.example .env` → `docker compose up -d` → `bash infra/check.sh`("모두 정상입니다"). 최초 실행은 이미지 다운로드 + ES 플러그인 빌드로 몇 분. 메모리 4GB 이상 권장(ES 1GB + Neo4j 1.5GB + PG), 8GB 노트북이면 `ES_JAVA_OPTS=-Xms512m -Xmx512m`.
- 데이터는 레포 루트 `data/<id>/`에 두면 컨테이너에서 바로 읽힌다: PG `/data/<id>/x.csv`(`COPY`), Neo4j `file:///<id>/x.csv`(`LOAD CSV`). ES는 마운트 없이 `_bulk`. `data/`는 README 빼고 git이 무시한다.
- `docker compose down`은 데이터 유지, `down -v`는 초기화(되돌릴 수 없음). 여러 실습이 한 인스턴스를 쓰므로 테이블·인덱스에 멤버 접두사를 붙인다(`do_dop_kakao_chunks`).
- `.env`의 `OPENAI_API_KEY`는 현황판 로컬 빌드와 실습에서 선택적으로 쓴다 → [[현황판]].

## 겪은 문제 · 배운 것

- **pg_trgm이 한글에 안 먹힘** (`show_trgm('한글')` = `{}`): DB가 순수 `C` 로케일로 생성된 것. `datctype`이 `C.UTF-8`이어야 한다. sese2204가 카카오톡 실습에서 겪고 compose를 `C.UTF-8`로 고쳤다 (2026-09-09) → [[PostgreSQL과-pgvector-함정]].
- 이미 만들어진 볼륨에는 `infra/postgres/init/01-extensions.sql`이 자동 적용되지 않는다. Neo4j 비밀번호 오류는 볼륨에 이전 비밀번호가 남은 것.
- ES가 계속 재시작 → 메모리 부족(`OutOfMemory`). Linux는 `vm.max_map_count=262144`. Colima는 기본 2GiB라 `--memory 6` 이상 (lys0611) → [[Elasticsearch-운영-함정]].
- `port is already allocated` → 로컬에 이미 PG/ES/Neo4j가 돌고 있다. M1/M2 Mac은 세 이미지 모두 arm64 지원.

| e0ng | 자체 compose: ES 8.15.0 + nori, PG16 + pgvector | 버전 불일치 |
| yujeong430 | 자체 compose: ES 9201, PG 5433 | 포트 불일치 |
| lys0611 | 자체 compose: `pgvector/pgvector:pg18`(18.6, pgvector 0.8.6), ES 9.5.3 + nori, Colima 4CPU/6GiB | pg18은 볼륨을 `/var/lib/postgresql`에 마운트해야 함. 공용(pg17, ES 9.1)으로 옮기려면 `pg_dump`나 재적재 필요 |
| sunghyun | 자체 compose: ES 8.19.21 + nori `127.0.0.1:19200`, PG 17 + pgvector 0.8.6 | 포트·버전·DB 설정이 공용과 다르다고 본인 명시. Compose 프로젝트 이름이 다른 로컬 실습과 같아 같은 호스트에서 컨테이너·볼륨을 공유할 수 있다 |
| dldusgh318 (W5) | 위 자체 compose에 **Neo4j 추가**, PG DSN `study@localhost:5433` | 공용 Neo4j(7687/7474)와 포트가 겹쳐 동시 실행이 안 될 수 있다. 자격증명이 문서에 평문으로 있어 위키에 옮기지 않는다 |

- heebindev는 PR #12(2026-09-16 머지)에서 자체 compose를 버리고 공용으로 옮겼다 — psql 접속이 `-U study -d knowledge_graph`에서 공용 `-U kg -d kg`로. 공용을 쓰는 멤버: sese2204, do-dop, kdyann, heebindev, ur2e, sdunge, Yeongeunn, **e0ng(05 실습; 02는 자체)**. 실습별로 다를 수 있으니 표는 실습 단위로 읽는다.
- **Neo4j를 실제로 쓴 첫 주차는 5주차**다: heebindev, e0ng, kdyann, Yeongeunn이 공용 5.26+APOC에 `MERGE`로 적재했고, dldusgh318은 자체 compose에 추가했다. 멤버 간 노드 격리는 전용 라벨 + `run` 속성(`KGStudyYeongeunn`, kdyann `W5_FACT`) → [[그래프-적재-Postgres와-Neo4j]]. 공용 Neo4j 비밀번호를 `cypher-shell` 명령줄에 평문으로 적은 문서가 있다 — `.env`의 `NEO4J_PASSWORD`로 참조하는 표기(heebindev)를 권한다.
- 설치 없이 **공개 SPARQL endpoint**(Wikidata·DBpedia)만으로 그래프 질의를 실습할 수 있다 (kdyann, yujeong430) → [[SPARQL]]. Triplestore(Jena·GraphDB)는 아무도 띄우지 않았다.
- sunghyun의 실습은 비공개 데이터·DB·모델이 없어 2026-10-01 정비 때 검색 실험을 재실행하지 못했다. 다른 사람이 재현하려면 데이터와 compose를 같이 받아야 한다.
- 버전이 다르면 클라이언트 라이브러리 메이저도 맞춰야 한다(`elasticsearch>=9,<10`) (lys0611).
