05 · Case 1

실제 질문 ①
이번 DB 장애도 지난번과 같을까?

배포 직후 API가 느려졌고,
같은 시간대에 DB 구조 변경도 있었습니다.

“이번 DB 부하가 지난번 FK DDL 배포 때처럼 migration lock 경합인지 확인해줘. 그때 보던 PI·RPS·앱 오류 기준으로 봐줘.”
비슷해 보이는 과거 경험은 좋은 출발점이지만, 아직 현재 원인의 증거는 아닙니다.

08 · Verification

과거 값이 아니라
검증 절차가 필요합니다

앱 오류 최초 발생 시각
migration SQL과 시작·종료 시각
같은 시간축의 전체 PI top wait·SQL
RPS·connection pool·외부 의존성
후보 원인별 일치·반증 증거
과거 결론 + 어떤 순서로 확인했는가 + 어떤 증거가 나오면 그 가설을 버려야 하는가

과거 사례는 가설의 출발점이지 현재 원인의 증명이 아닙니다.

23 · Case 2 Revisited

메모리 누수 질문도 달라집니다

과거 범인 재사용
