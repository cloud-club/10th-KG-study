# 프로젝트 데이터 선정

## 시작점

취업 준비에 활용할 수 있도록 프로젝트에서 **왜 그런 설계를 선택했는지** 찾아볼 수 있는 지식베이스를 만들고 싶었다. 최종 기능이나 기술 스택뿐 아니라, 당시 검토한 대안과 판단의 근거를 정리하는 것이 목표였다.

처음 생각한 데이터는 프로젝트 회의와 강사 피드백 녹음이었다. 노션에 적지 않고 구두로 나눈 의견까지 연결하면 의사결정 과정을 복원할 수 있을 것 같았다. 하지만 녹음 파일을 유실해 다른 데이터를 검토했다.

GitHub도 후보였지만, 우선 팀원들과 함께 작성한 프로젝트 Notion으로 시작하기로 했다. 금융 도메인의 낯선 개념을 공부하며 조사한 자료가 많았고, 회의록·멘토링·기획·명세도 함께 남아 있었다. 프로젝트가 만들어진 배경을 살펴보기 좋고, 하위 페이지까지 export할 수 있어 수집하기도 편했다.

## 데이터 후보

| 후보 | 담긴 정보 | 선택 |
|---|---|---|
| 회의·피드백 녹음 | 구두 논의와 설계 판단 | 파일 유실 |
| GitHub | 코드와 변경 이력 | 연계 후보 |
| 프로젝트 Notion | 도메인 조사·회의록·멘토링·명세 | 선정 |
| Discord | 공유 자료와 팀 논의 | 연계 후보 |

## 찾고 싶은 내용

- 이 기능은 어떤 문제를 해결하려고 추가했는가?
- 어떤 대안을 검토했고, 무엇을 이유로 선택했는가?
- 멘토링 피드백이 어떤 설계 변경으로 이어졌는가?

Notion 기록과 실제 구현을 연결할 수 있다면 설계와 코드의 차이도 살펴볼 수 있다. 다만 구현 코드만으로 당시 의도를 단정하기는 어렵기 때문에 회의록이나 명세의 근거를 함께 찾는 것이 중요하다.

## 선정한 자료

팀 Notion에 모인 금융 도메인 조사, 회의록, 멘토링 기록, 기획·API 명세를 대상으로 정했다. 하위 페이지도 함께 내보낼 수 있어 문서 사이의 맥락을 살펴보기 좋았다.

전처리 방식과 적재 규모는 [3주차 실습 기록](../labs/03-notion-ingest/README.md)에 정리했다.
