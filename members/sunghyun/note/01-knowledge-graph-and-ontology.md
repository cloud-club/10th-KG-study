# 01. 지식 그래프와 온톨로지 기초

> 참고 자료:
>
> - 개인 Notion 1 Week
> - 온톨로지 세미나 PDF

## 한 줄 요약

데이터를 대상과 관계로 연결해서 표현하는 방법과, 그때 필요한 기본 용어들을 공부했다.

## 핵심 개념

- 트리플(Triple): 하나의 정보를 주어 - 술어 - 목적어로 나타낸 것이다.
- 그래프(Graph): 데이터를 노드와 엣지로 연결한 구조다.
- 지식 그래프(Knowledge Graph): 여러 정보를 관계로 연결해서 저장한 그래프다.
- 온톨로지(Ontology): 어떤 개념과 관계를 사용할지 미리 정한 규칙이다.
- RDF: 데이터를 트리플 형태로 표현하기 위한 표준이다.
- URI: 각각의 대상을 구분하기 위한 고유한 식별자다.
- Turtle: RDF 데이터를 사람이 읽기 쉽게 작성하는 문법이다.

## 상세 정리

### 트리플

트리플은 하나의 정보를 세 부분으로 나누어 표현한다.

~~~text
주어 - 술어 - 목적어
~~~

예를 들면 다음과 같다.

~~~text
이성현 - 참여한다 - KG 스터디
KG 스터디 - 사용한다 - PostgreSQL
~~~

처음에는 문장을 굳이 세 부분으로 나누는 이유가 궁금했다.
공부하면서 정보를 이런 식으로 나누면 사람, 스터디, 기술 같은 대상을 구분하고 서로 어떤 관계가 있는지 연결할 수 있다는 것을 알게 되었다.

### RDBMS와 그래프

RDBMS는 데이터를 행과 열로 이루어진 테이블에 저장한다.
정해진 형식의 데이터를 저장하고 조회할 때 사용하기 좋다.

하지만 데이터 사이의 관계가 많아지면 여러 테이블을 만들어야 하고, 조회할 때 조인도 많아질 수 있다.
그래프는 데이터 자체보다 데이터 사이의 관계를 중심으로 표현한다.

~~~text
노드(Node) = 대상
엣지(Edge) = 대상 사이의 관계
~~~

예를 들어 사람, 스터디, 기술을 각각 노드로 만들고 참여한다, 사용한다를 엣지로 연결할 수 있다.

~~~text
[이성현] --참여한다--> [KG 스터디] --사용한다--> [PostgreSQL]
~~~

RDBMS가 좋지 않다는 뜻은 아니다.
표처럼 정리하기 좋은 데이터에는 RDBMS가 잘 맞고, 연결 관계를 따라가는 일이 중요할 때는 그래프가 이해하기 쉬울 수 있다.

### 지식 그래프

지식 그래프는 여러 대상과 관계를 그래프 형태로 저장한 것이다.

단순히 정보를 모아두는 것보다 어떤 정보가 서로 연결되어 있는지를 확인할 수 있다는 점이 중요하다.
예를 들어 사람 → 참여한 스터디 → 사용한 기술처럼 관계를 이어서 정보를 찾을 수 있다.

이처럼 답을 찾기 위해 관계를 여러 번 따라가는 질문을 다중 홉 질문(Multi-hop Question)이라고 한다.

### 온톨로지

같은 의미의 관계도 사람마다 다르게 작성할 수 있다.

~~~text
이성현 - 참여한다 - KG 스터디
이성현 - 소속된다 - KG 스터디
~~~

사람이 보기에는 비슷하지만 컴퓨터는 참여한다와 소속된다를 다른 관계로 볼 수 있다.
그래서 데이터를 만들기 전에 사용할 개념과 관계를 정할 필요가 있다.

온톨로지는 특정 분야에서 사용할 개념과 관계를 정의한 규칙이다.

~~~text
개념: 사람, 스터디, 기술
관계: 참여한다, 사용한다
~~~

지식 그래프가 실제 정보를 저장한 데이터라면, 온톨로지는 그 정보를 어떤 방식으로 작성할지 정한 약속이라고 이해했다.

### RDF와 URI

RDF는 정보를 트리플 형태로 표현하기 위한 표준이다.
RDF에서는 대상과 관계를 정확히 구분하기 위해 URI를 사용할 수 있다.

예를 들어 같은 이름을 가진 대상이 여러 개 있더라도 URI가 다르면 서로 다른 대상으로 구분할 수 있다.

~~~text
https://example.com/person/lee-seonghyeon
https://example.com/study/kg-study
~~~

URI가 웹 주소처럼 생겼지만 항상 실제 페이지가 있어야 하는 것은 아니다.
여기서는 각각의 대상을 구분하는 고유한 이름으로 사용한다.

### Turtle

Turtle은 RDF 데이터를 사람이 읽기 쉽게 작성할 수 있는 문법이다.
긴 URI를 매번 쓰지 않고 앞부분을 prefix로 줄여서 사용할 수 있다.

~~~turtle
@prefix ex: <https://example.com/> .

ex:seonghyeon ex:participatesIn ex:kgStudy .
ex:kgStudy ex:uses ex:postgresql .
~~~

위 내용은 다음 두 문장을 트리플로 표현한 것이다.

- 이성현은 KG 스터디에 참여한다.
- KG 스터디는 PostgreSQL을 사용한다.

## 예시 / 코드

Turtle로 작성한 데이터를 조회할 때는 SPARQL을 사용할 수 있다.

~~~sparql
PREFIX ex: <https://example.com/>

SELECT ?technology
WHERE {
  ex:seonghyeon ex:participatesIn ?study .
  ?study ex:uses ?technology .
}
~~~

아직 직접 실행해 본 코드는 아니다.
