## 갈리는 지점

- **인프라**: 공용 compose(sese2204, do-dop, kdyann, heebindev, ur2e) vs 자체 compose(dldusgh318, e0ng, yujeong430, lys0611). 자체 쪽은 ES·PG 버전과 포트가 공용과 어긋나 데이터를 그대로 못 옮긴다 → [[로컬-인프라]].
- **임베딩**: 로컬 bge-m3/KURE 1024d(4명) / 로컬 소형 384~768d(3명) / 외부 API(ur2e, 합성 데이터). 개인 대화를 다루는 멤버는 전부 로컬 → [[임베딩-모델-선택]], [[개인-데이터-가명화와-공개-범위]].
- **청킹**: 발화자 섞는 세션(30분: sese2204, lys0611 / 4시간: jjinthung) vs 같은 발신자 연속(1분: do-dop / 5분: e0ng) vs 날짜별(yujeong430) vs 문서 구조(heebindev, ur2e, dldusgh318) → [[청킹-전략]].
- **검색 단위**: ur2e는 "세 방식이 같은 청크를 써야 비교가 의미 있다"고 못 박았고, do-dop(ES=메시지, pgvector=청크, grep=원본)·heebindev·yujeong430(grep=원본)은 방식별 단위가 다르다. lys0611은 grep이 메시지 단위·순위 없음이라 Recall 표에서 뺐다 → [[검색의-세-세대]].
- **질의**: kdyann·ur2e·lys0611은 같은 질의를 세 방식에, yujeong430은 방식마다 다른 질의(`재수강` / `재수강 신청` / `수업을 다시 듣는 신청`).
- **평가**: 정답 라벨이 있는 곳은 dldusgh318·lys0611·ur2e·jjinthung. 지표는 제각각 → [[RAG-평가-지표]].
- **하이브리드 이후**: RRF까지 간 곳은 sese2204·dldusgh318·lys0611, RAG 생성까지 간 곳은 dldusgh318·lys0611, 실패 분류·그래프 스키마까지 간 곳은 lys0611(failures.md)·dldusgh318(W4 예고).

## 공용 인프라로 모으려면

- 자체 compose 데이터는 `pg_dump`나 재적재가 필요하다(lys0611이 명시). 공용 인스턴스에서는 테이블·인덱스에 멤버 접두사를 붙인다(do-dop, ur2e 관례).
- 같은 골든셋으로 비교하려면 질문 **유형**(exact / semantic / hard 등)과 라벨링 절차(pooling, evidence group, content_hash)를 공용화하는 게 먼저다 → [[RAG-평가-지표]] 열린 질문.
