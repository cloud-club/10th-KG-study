# 06. 쿼리 재작성

> 참고 자료:
> - HyDE (2022)
> - RAG-Fusion, Step-back prompting, Adaptive RAG
> - DSPy

## 한 줄 요약

쿼리 재작성 기법은 전부 LLM 호출을 추가하므로, 회수율이 이미 충분하면 붙일수록 순손해다.

## 핵심 개념

- 멀티턴이면 대화형 쿼리 재작성(지시대명사 해소)은 필수
- Multi-query / RAG-Fusion은 구현이 쉽고 가성비가 좋다
- HyDE는 질문-문서 임베딩 공간의 비대칭성을 가상 답변 문서로 우회한다
- 다단계 프롬프트 파이프라인은 손으로 튜닝하면 금방 한계 → DSPy가 전체를 하나의 최적화 대상으로 다룬다

## 상세 정리

| 기법 | 설명 | 비고 |
|---|---|---|
| 대화형 쿼리 재작성 | "그거 얼마야?" → 지시대명사 해소 | 멀티턴이면 필수 |
| Multi-query / RAG-Fusion | 변형 쿼리 3~5개 생성 → 각각 검색 → RRF 융합 | 구현 쉬움, 가성비 좋음 |
| **HyDE** (2022) | 질문에 대한 *가상의 답변 문서*를 LLM으로 생성 → 그걸 임베딩해 검색 | 질문-문서 임베딩 공간의 비대칭성 우회. 개념적으로 배울 게 많음 |
| Step-back prompting | 구체 질문에서 상위 개념 질문을 뽑아 함께 검색 | |
| 쿼리 분해 | 멀티홉 질문을 서브 질문으로 | |
| 라우팅 / Adaptive RAG | 애초에 검색이 필요한 질문인지 분류 | |

> ⚠️ 이 기법들은 전부 LLM 호출을 추가 → 지연과 비용이 곱으로 증가.
> 회수율이 이미 충분한데 붙이면 **순손해**.

**DSPy와의 접점**: 쿼리 재작성 프롬프트 + 리랭킹 판정 프롬프트 + 생성 프롬프트가 겹겹이 쌓인
다단계 파이프라인은 손으로 튜닝하면 금방 한계. DSPy는 그 전체를 하나의 최적화 대상으로 다룸.
