# 0세대 검색 - grep 문자열 매칭

## 한 줄 요약

grep은 파일의 각 줄이 입력한 패턴과 일치하는지를 검사해 보여 주는 도구다. 정확한 표현을 빠르게 찾지만, 표현이 달라진 같은 의미와 결과의 관련도 순위는 다루지 못한다.

## grep은 무엇을 저장하고 어떻게 찾는가

grep 자체는 별도 검색 인덱스를 만들지 않는다. 원본 텍스트 파일을 그대로 두고, 질의할 때 파일을 처음부터 읽어 패턴에 맞는 **줄**을 출력한다. GNU grep은 기본 정규표현식(BRE), 확장 정규표현식(ERE), PCRE 문법을 지원한다. 정규표현식이 아니라 입력 문자열을 있는 그대로 찾고 싶다면 `-F`를 사용한다.

```text
저장: 원문 텍스트 파일
질의: "재수강"
처리: 각 줄에 "재수강" 패턴이 있는지 검사
결과: 일치한 줄 + 파일명/줄 번호
```

`-R`은 하위 폴더까지, `-n`은 줄 번호, `-i`는 대소문자 무시 옵션이다.

```bash
grep -RniF "재수강" ./documents/
```

grep의 검색 비용은 대체로 질의 시 읽어야 하는 전체 텍스트 양에 비례한다. 즉, 인덱스를 만드는 사전 비용은 없지만, 데이터가 커지고 질의가 반복될수록 같은 파일을 계속 훑는 비용이 쌓인다.

## 문자열 매칭과 정보 검색의 차이

grep은 **조건을 만족하는 줄을 판정**한다. 반면 정보 검색(IR)은 보통 질의와 문서 사이의 관련도를 계산해 **좋은 문서를 순위화**한다. 이 차이 때문에 grep의 결과는 "맞음/틀림"에 가깝고, BM25와 벡터 검색의 결과는 점수와 정렬 순서를 가진다.

정규표현식은 `재수강( 신청)?`처럼 알려진 표기 변형을 표현할 수 있지만, 사람이 미리 규칙을 설계해야 한다. `수업을 다시 듣는다`가 `재수강`을 뜻한다는 의미 관계를 자동으로 추론하지는 않는다.

## 왜 "내 문서를 찾기"에는 부족한가

### 1. 표현 불일치

문서에 `학기재수강 신청`이라고 쓰여 있는데 사용자가 `이번 학기 재수강 언제까지야?`라고 물으면, 문장 전체를 찾는 grep은 결과를 내지 못한다. 공백 하나가 다른 `학기 재수강`도 별도 문자열이다. 정규표현식으로 변형을 일부 포괄할 수는 있어도, 동의어와 문장 의미를 일반적으로 이해하는 것은 아니다.

### 2. 관련도 순위가 없다

grep 결과의 기본 순서는 파일을 읽은 순서와 줄의 위치다. "이 줄이 질의에 얼마나 답이 되는가"를 계산하지 않는다. 수백 개가 일치하면 사람이 다시 읽고 판단해야 한다.

### 3. 문맥 단위가 줄이다

한 공지의 날짜, 대상, 신청 방법이 여러 줄로 나뉘면 한 줄만 봐서는 답하기 어렵다. `-C 3`처럼 앞뒤 문맥을 출력할 수 있지만, 이는 검색 결과를 점수화하거나 문서 단위로 묶는 기능은 아니다.

`-C 3`처럼 앞뒤 문맥을 함께 출력할 수는 있지만, 이는 검색 결과를 점수화하거나 문서 단위로 묶는 기능은 아니다.

## grep이 가장 좋은 경우

- 정확한 고유명사, 코드, URL, 오류 문구를 찾을 때
- 데이터가 작고 한두 개의 파일을 빨리 확인할 때
- 검색 결과가 왜 나왔는지 한 글자 단위로 설명해야 할 때

## 다른 검색 방식과의 관계

| 질문 | grep | 키워드 검색(BM25) | 벡터 검색 |
| --- | --- | --- | --- |
| `HNSW`가 포함된 줄을 찾아줘 | 강함 | 강함 | 가능하지만 과함 |
| `재수강 관련 공지`를 찾아줘 | 정확한 표현이 있어야 함 | 단어가 겹치면 강함 | 의미가 비슷하면 강함 |
| 결과 순위 | 없음 | BM25 점수 | 유사도 점수 |
| 사전 준비 | 없음 | 토큰화·역색인 | 청킹·임베딩·벡터 인덱스 |
