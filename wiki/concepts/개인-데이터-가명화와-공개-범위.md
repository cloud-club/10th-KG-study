> 스터디 데이터가 개인 카카오톡·노션·인스타그램이라 "무엇을 레포에 올리고, 무엇을 외부 API에 보내고, 무엇을 위키에 옮기는가"가 첫 설계 결정이다. 멤버 전원이 원본을 git에서 제외했고, 개인 대화를 다루는 멤버는 전부 로컬 임베딩을 골랐으며, lys0611은 가명화를 임베딩 **앞**에 두는 파이프라인과 그 법적·약관 근거를 정리했다.

## 스터디 공통 규칙

- 원본 데이터(`data/`, `data/raw/`)는 git이 무시한다. 레포 루트 `.gitignore`와 랩 폴더 `.gitignore`가 둘 다 있어야 실명 매핑표(`name_map.json`)와 `.env`가 안 올라간다. 커밋 전 `git status`에 `members/<id>/…`만 보여야 하고, `git check-ignore -v`로 원본이 실제로 무시되는지 확인한다 (lys0611).
- 코드·실행 문서·결과 캡처만 공유한다 (kdyann). 검색 결과를 공개 문서에 옮길 때는 원문 스니펫이 아니라 청크 ID·점수·관련성 요약만 남긴다 (lys0611 compare.md). dldusgh318은 샘플 5건만 180자 절단·이메일/전화 마스킹해 구조 확인용으로 커밋했다.
- 토큰 분석 실습을 할 때는 실제 대화 대신 직접 만든 예시 문장을 쓴다 (do-dop). 시험 대비 자료·기출문제는 실습에서 제외 (heebindev).
- 위키(`wiki/`)에는 대화 내용·이름·장소를 옮기지 않고 통계(건수·기간)만 적는다 (루트 `CLAUDE.md` 규칙). 이 페이지도 그 규칙을 따른다.

## 가명화를 어디에 두는가 (lys0611)

- 파이프라인: 파싱 → **가명화 + PII 마스킹** → Postgres 적재 → 청킹 → 임베딩 → ES 색인. 마스킹은 추출·전송 **전**에 해야 의미가 있다. 레포가 public이고 임베딩이 외부 API로 나갈 수 있기 때문.
- 마스킹 대상: 휴대폰·유선 전화, 주민등록번호, 카드번호, 하이픈 포함 10~16자리(계좌 추정), 하이픈 없는 10~14자리 숫자열, 이메일 → `[전화번호]` 같은 토큰. 본문 속 이름도 같은 가명으로 바꾼다(`철수형 시간 되나` → `하람형 시간 되나`). 질문 문자열에도 같은 매핑을 적용한다.
- 두 방을 **같은 `name_map.json`**으로 처리해 겹치는 사람이 같은 가명을 유지한다. 나중에 사람 노드를 하나로 합치기 위해서다 → [[지식그래프와-온톨로지]].
- 한계: 별명·초성(`ㅊㅅ`)·주소·직장명은 자동으로 못 잡는다. 이름 뒤에 `학생`처럼 다른 명사가 바로 붙은 경우도 놓쳤다. 잔여 전화번호는 `grep -oE "01[016789]-?[0-9]{3,4}-?[0-9]{4}"`로 점검.
- 가명화의 부작용: 마스킹된 `[계좌번호]`를 LLM이 "값이 없다"로 읽어 과잉 거절했다. 프롬프트에 "값이 가려져 있다"고 답하게 해야 한다 → [[RAG-루프와-근거-인용]].
- 근거 사슬(lys0611 readings 1주차): 2025 대법원 판례 해설("유효한 사전 동의 범위 안이면 누설이 아니다" → 방 멤버 동의 + 가명화), Gemini 무료 티어 약관(제출 콘텐츠를 제품 개선에 쓰고 사람이 검토할 수 있으며 개인정보를 넣지 말라고 명시 → 무료 티어를 쓰지 않은 이유), OpenAI API 데이터 정책(명시적 옵트인 없이는 학습에 안 씀 → 유료 API를 쓸 때의 기준).
