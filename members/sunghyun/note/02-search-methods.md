# 02. grep, BM25, 벡터 검색 정리

> 참고 자료:
>
> - GNU grep manual
> - Elasticsearch similarity settings
> - pgvector 문서

## 한 줄 요약

같은 문서를 grep, BM25, 벡터 검색으로 찾아보면서 각 검색 방식의 차이를 공부하고 있다.

## 핵심 개념

- grep: 파일에서 입력한 문자열이나 패턴을 찾는다.
- 역색인(Inverted Index): 단어가 들어 있는 문서의 위치를 미리 저장한 구조다.
- BM25: 검색어와 문서가 얼마나 관련 있는지 점수를 계산한다.
- 임베딩(Embedding): 문장을 의미를 담은 숫자 배열로 바꾸는 과정이다.
- 벡터 검색(Vector Search): 질문과 의미가 가까운 문서를 찾는 방식이다.
- pgvector: PostgreSQL에서 벡터를 저장하고 검색할 수 있게 해 주는 확장 기능이다.

## 상세 정리

### grep

grep은 검색어와 같은 문자열이 포함된 줄을 찾는다.
별도의 검색 서버가 없어도 파일에서 바로 사용할 수 있다는 점이 편리하다.

~~~bash
grep -Rni "프로세스" data/
~~~

하지만 문서에 검색어와 같은 단어가 없으면 의미가 비슷해도 찾지 못한다.
또한 검색 결과에 관련도 순위를 매겨주지는 않는다.

### 역색인

문서가 많아질수록 검색할 때 모든 문서를 처음부터 읽는 것은 오래 걸린다.
역색인은 단어를 기준으로 그 단어가 들어 있는 문서를 미리 정리한다.

~~~text
프로세스 → 문서 1, 문서 2
스레드   → 문서 2, 문서 3
메모리   → 문서 4
~~~

책 마지막에 있는 찾아보기와 비슷하다고 이해했다.
Elasticsearch도 데이터를 저장할 때 역색인을 만들어 검색에 사용한다.

### BM25

BM25는 검색어가 문서에서 얼마나 중요한지 계산하고, 점수가 높은 문서를 먼저 보여준다.

공부하면서 이해한 특징은 다음과 같다.

- 한 단어가 반복된다고 점수가 계속 크게 올라가지는 않는다.
- 긴 문서가 무조건 높은 점수를 받지 않도록 문서 길이를 보정한다.
- 전체 문서에서 드물게 등장하는 단어를 더 중요하게 볼 수 있다.

한국어는 조사와 어미가 붙기 때문에 단어를 어떻게 나누는지도 중요하다.
Elasticsearch에서는 nori 분석기를 이용해 한국어 형태소를 분석할 수 있다.

### 벡터 검색

벡터 검색은 문장을 임베딩 모델에 넣어 숫자 배열로 변환한 다음, 가까운 벡터를 찾는다.

~~~text
서버 연결에 실패했다
→ [0.12, 0.83, -0.31, ...]
~~~

이 방법을 사용하면 문서와 질문에 같은 단어가 없어도 의미가 비슷한 내용을 찾을 수 있다.
질문과 문서는 같은 임베딩 모델로 변환해야 한다.

pgvector에서는 PostgreSQL에 벡터를 저장하고 거리 연산자로 가까운 데이터를 찾을 수 있다.

### 검색 방식 비교

각 검색 방식은 잘하는 일이 다르다.

- 정확한 에러 코드나 이름 찾기: grep 또는 BM25가 유리할 수 있다.
- 표현이 다른 비슷한 문장 찾기: 벡터 검색이 유리할 수 있다.
- 키워드와 의미가 모두 중요할 때: 두 결과를 함께 사용하는 방법이 필요하다.

한 가지 검색 방식이 항상 좋은 것은 아니고, 검색하려는 데이터와 질문에 따라 선택해야 한다.

## 예시 / 코드

pgvector에서 코사인 거리가 가까운 데이터를 찾는 SQL의 형태는 다음과 같다.

~~~sql
SELECT content,
       embedding <=> :query_embedding AS distance
FROM chunks
ORDER BY distance
LIMIT 5;
~~~

아직 같은 데이터로 세 가지 검색 방식을 모두 비교하지는 못했다.
다음 실습에서는 같은 질문을 사용해 결과가 어떻게 달라지는지 확인할 예정이다.
