# 06. GraphRAG와 에이전틱 검색 비교

관련 노트: [6주차 학습 기록·실제 비교 결과](../../notes/06-graphrag-and-agentic-search.md).

회사 실습의 검색·그래프 확장·실행 기록 로직을 합성 데이터로 옮겼다. 공개 예제는 JSON 그래프를 사용하며 운영 실습의 Neo4j 전체 집계나 브라우저 UI를 그대로 배포한 것은 아니다. 샘플은 W5 예제와 같은 ID를 사용한다.

## W6 공부·실습과 코드의 대응

| Notion 항목 | 이 실습에서 확인할 것 |
|---|---|
| 로컬/글로벌/Text2Cypher 공부 | 로컬 조회·질의 생성은 실행, 커뮤니티 요약은 개념만 |
| 하이브리드 리트리버 | `src/retriever.py`: 벡터·BM25·RRF, 엔티티 ID, 그래프 확장 |
| ① v1 → v2 | `src/compare.py`: 같은 질문·검색 결과에 그래프를 더한 컨텍스트 비교 |
| ② 같은 질문·정답 비교 | 답변·누락·출처·시간·토큰, 부분 검색과 전체 집계 구분 |
| ③ Text2Cypher | `src/text2cypher.py`: 생성 보류와 생성된 미검증 질의 구분 |
| 추가 에이전틱 비교 | `src/agentic.py`: 그래프 도구 유무에 따른 도구 선택·결과 |

## 준비

Python 3.10 이상이면 코드 자체는 표준 라이브러리로 실행된다. Ollama와 `qwen3-embedding:0.6b`가 필요하다. 답변은 기본 `qwen2.5:7b`를 쓴다.

GLM을 사용할 때는 아래 환경 변수를 설정한다. 키는 셸에서 별도로 주입하고 파일이나 Git에 넣지 않는다.

- `LLM_API_KEY`: 모델 API 키.
- `LLM_BASE_URL`: 기본 `https://api.mangoboost.io/v1`.
- `LLM_MODEL`: 기본 `zai-org/GLM-5.2`.

선택 변수는 `OLLAMA_URL`, `OLLAMA_MODEL`, `EMBED_MODEL`이다.

## 1. 동일 질문 v1/v2

```bash
python src/compare.py 'v0.1.0 1차에서 어떤 케이스가 실패했고 어떤 빌드로 테스트했나?'
```

v1은 정확 벡터 검색+BM25+RRF 청크만, v2는 같은 검색 결과에 양방향 3-hop 그래프를 추가한다. `outputs/comparison.json`에 답변·컨텍스트·시간·토큰을 저장한다. Top-k와 제한된 서브그래프만으로 전체 집계를 보장하지 않는다. 이 예제의 시간은 답변 생성 구간이며 아래 실제 실험의 전체 시간과 다르다.

## 2. 그래프 없이 에이전틱 검색 / 그래프 도구 추가

```bash
python src/agentic.py 'v0.1.0 1차에서 어떤 케이스가 실패했고 어떤 빌드로 테스트했나?'
```

두 방식 모두 모델이 청크 검색·원문 읽기·종료를 선택한다. 그래프 방식에는 ID 기준 이웃 조회 도구를 추가한다. 조회 예산은 각각 5회, 모델 호출은 최대 6회다. `outputs/agentic.json`에 각 도구 요청과 받은 결과를 저장한다.

운영 실습에서는 그래프 도구가 조회 전용 Cypher를 실행했다. 이 공개 예제는 임의 Cypher를 실행하지 않고 JSON 그래프의 1-hop 도구로 제한했다. API 응답이 JSON이 아니거나 도구 예산을 넘으면 오류를 기록한다. 실패도 결과로 확인한다.

## 3. Cypher 생성

```bash
python src/text2cypher.py 'v0.1.0 실패 Case Run의 케이스 이름과 실행 차수는?'
python src/text2cypher.py '관련 커밋이 있으니 이슈가 수정 완료인가?'
```

생성 결과는 `outputs/generated-cypher.json`에 저장한다. 생성된 문자열을 자동 실행하지 않는다. W5의 라벨·관계와 맞는지 검토한다. 두 번째 질문은 참조 관계만으로 완료를 판단할 수 없으므로 `answerable:false`가 적절하다.

## 실제 화면으로 확인한 세 가지

### 1. 근거 부족으로 생성 보류

![관련 커밋으로 수정 완료를 판단할 수 없어 Cypher 생성 보류](../../assets/week6-cypher-insufficient-evidence.png)

질문은 “관련 커밋이 있으니 이슈가 수정 완료인가?”다. 관련 커밋은 참조일 뿐 완료 증명이 아니므로 `answerable:false`가 적절하다. 이것을 실행 오류로 분류하지 않는다.

### 2. 생성된 Cypher도 검토가 필요하다

![실패 Case Run 개수 질문에 생성된 미검증 Cypher](../../assets/week6-cypher-generated-unverified.png)

화면에서는 `execution:null`이다. 생성문은 `PART_OF_RUN` 방향과 Test Run 라벨이 실제 모델과 다르고, 개수 질문에 count 없이 행을 반환했다. [오류별 설명과 실제 스키마 교정 예시](../../notes/06-graphrag-and-agentic-search.md#cypher가-생성됐지만-정답으로-확정할-수-없는-화면)를 참고한다.

검토할 순서는 질문의 범위 → 라벨·kind → 관계 방향 → 속성 위치 → DISTINCT·집계 → 파라미터 값이다. 공개 예제의 라벨은 `StudyW5`, 화면의 실제 실습은 `W56Entity`이므로 문자열을 그대로 실행하지 않는다.

### 3. 그래프 도구가 있어도 잘못된 경로면 오답

![Test Case 미연결 Task의 에이전틱 검색 비교](../../assets/week6-agentic-no-cases-comparison.png)

GLM-5.2의 동일 질문에서 그래프 없는 방식은 UNKNOWN, 그래프 방식은 잘못된 직접 경로를 조회해 18개라고 답했다. 정답은 당시 그래프 기준 13개로 양쪽 모두 해당 질문은 0/1이다. `Task→Issue→Test Case` 경로가 필요했지만 모델은 `Task→Test Case`만 봤다.

공개 샘플로는 이 18개/13개를 재현하지 않는다. 이 화면은 실제 회사 코퍼스에서 실행한 별도 결과이며, 공개 코드는 작은 합성 데이터에서 같은 오류 검토 방법을 연습하는 용도다.

## 릴리즈 다중 홉에서 비교할 질문과 범위

실제 UI에서는 다음처럼 개수를 명확히 요청했다.

> v0.1.0 릴리즈에 배정된 Harbor 빌드에서 실행한 Test Run은 몇 개이고, Case Run 통과·실패는 각각 몇 개인가? 실행 차수와 기준 빌드, 케이스명을 함께 알려줘.

- v1: 처음 검색한 청크에서 확인한 케이스·결과만 표시한다. 일부 기록으로 전체 개수를 단정하면 안 된다.
- v2: Release←파일→Test Run←Case Run 관계로 대상 실행을 모아 집계한다.
- 답변에 Test Run 수, 차수, 기준 파일, 케이스명·결과를 분리해 기록한다.
- 파일에 연결된 실행만 센 것인지, 전체 과거 이력인지 조건을 명시한다.

당시 실제 UI의 파일 연결 집계는 두 릴리즈 각각 Test Run 2개·통과 4·실패 0이었다. 빌드 미연결 실행은 제외했으며, 공개 샘플의 정답과 다르다. 이 공개 리트리버는 Top-k와 3-hop 확장까지만 지원하므로 전체 버전 집계가 필요하면 `release-results.cypher`의 범위 질의를 별도로 확인한다.

`release-results.cypher`의 샘플 예상 집계는 파일 1개·Test Run 1개·통과 0·실패 1이다. JSON의 ID·kind·관계 방향과 대조했으며, 이번 문서 업데이트에서 이 추가 질의를 Neo4j에 실행하지는 않았다.

## 기준 답과 기록

샘플의 정답은 `case:1` 실패, Test Run `run:1` 1차, 파일 `file:1`, 릴리즈 `v0.1.0`이다. 이것은 합성·시뮬레이션 데이터다.

실제 회사 코퍼스로 실행한 에이전틱 실험은 별도이며, 그래프 없이 4/9·그래프 도구 추가 3/9였다. 도구별 토큰·시간·사실 항목 점수는 `measured-summary.json`에 원문 없이 보존했다. 결과와 범위 오류는 [학습 노트](../../notes/06-graphrag-and-agentic-search.md)에 기록했다. 확정된 API 단가가 없어 화폐 비용은 계산하지 않았다.

게시 전 검색의 오프라인 스모크 검증, 그래프 확장, Python 구문 검사를 실행했다. 새 공개 코드의 전체 GLM·Ollama 답변 호출은 재실행하지 않았다. 회사 실습에서 이미 측정한 수치를 공개 예제의 성능으로 주장하지 않는다.
