# pgvector 와 Elasticsearch 검색 방식 비교

내 작업기록을 자연어로 찾으려면 뭘로 검색해야 하는지 정리하려고 시작한 메모.

## grep

- 정확한 문자열만 찾는다. `인증서` 로 검색하면 `certificate` 라고 쓴 문서는 못 찾는다.
- 내 메모는 한글/영어를 섞어 쓰기 때문에 이게 실제로 문제가 된다.
- 대신 명령어나 에러 메시지처럼 정확한 문자열을 찾을 때는 제일 확실하다.

## BM25 (Elasticsearch)

- 단어 빈도와 문서 길이로 점수를 낸다. 여전히 **단어가 겹쳐야** 찾는다.
- 한글은 형태소 분석기가 필요하다. nori 없이는 "인증서가" 와 "인증서" 가 다른 토큰이 된다. → [[es-nori-인덱스-재색인]]
- 에러 코드, 고유명사, 명령어에 강하다. `x509`, `ImagePullBackOff` 같은 건 BM25 가 이긴다.

## 벡터 검색 (pgvector)

- 문장을 임베딩해서 의미가 가까운 걸 찾는다. 단어가 안 겹쳐도 찾을 수 있다.
- "그때 그 인증서 문제 어떻게 고쳤지" 같은 질문이 여기서 산다. 문서에 "그때" 나 "고쳤지" 는 없다.
- 반대로 정확한 토큰 매칭은 약하다. 숫자나 코드값이 뭉개진다.

## 그래서 하이브리드

내 경우 질문이 두 종류로 나뉜다.

1. "그거 명령어 뭐였지" → 정확한 문자열 (grep/BM25 유리)
2. "왜 그렇게 결정했지", "비슷한 일 전에 있었나" → 의미 (벡터 유리)

한쪽만 고르면 다른 쪽 질문이 죽는다. 그래서 둘 다 돌리고 점수를 합치는 방향으로 가야 할 것 같다.
