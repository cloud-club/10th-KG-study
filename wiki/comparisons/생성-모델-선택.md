> RAG 답변과 트리플 추출에 쓴 생성 모델의 레지스트리. 열 멤버가 아홉 가지 모델을 썼고 선택 이유는 성능이 아니라 **데이터 민감도**로 갈렸다 — 개인 카카오톡·회사 자료는 로컬 7B, 공개 자료·강의 노트·개인 Notion은 외부 API. 같은 모델 계열(`exaone3.5`)을 쓴 멤버가 둘(lys0611, do-dop)이라 비교 가능한 드문 지점이 있다. 역할별 비교는 [[모델-역할-분담]], 임베딩은 [[임베딩-모델-선택]].

## 갈리는 지점

- **로컬 ↔ 외부의 기준이 일관되지 않는다.** lys0611·jjinthung은 같은 개인 카카오톡인데 하나는 로컬, 하나는 외부. e0ng·dldusgh318의 개인 활동 기록과 Yeongeunn의 팀 비공개 문서는 추출을 외부 API로 보냈다. 임베딩에서는 전원 로컬이었던 경계가 생성·추출에서는 흐려졌다 → [[개인-데이터-가명화와-공개-범위]].
- **모델 크기로 풀리는 문제와 안 풀리는 문제** (do-dop): 자기 점검("근거가 부족하니 다시 검색")은 2.4b → 7.8b로 해결됐지만, 쥐고 있는 두 사실을 잇는 추론은 7.8b도 못 했다. 환각(sunghyun의 약어 확장)은 7B급 로컬에서 나왔고, 외부 모델은 "자료만으로 알 수 없다"고 답했다 — 단 질문이 달라져 모델 우열로 해석하지 않았다.
- **비교 절차** (Yeongeunn 08): 먼저 검색을 고정 → 같은 근거를 A·B에 → **모델 이름을 가리고 사람이 채점** → 토큰·지연·실패 기록 → end-to-end는 별도 → oracle로 검색/생성 분리. "RAG ≠ 파인튜닝, 온톨로지 설계도 학습과는 다른 작업이다."
- 공개 벤치마크(MMLU·TruthfulQA·HELM·Ragas)는 버전·분할·프롬프트·채점 방식을 함께 적어야 하고 "학습 중 공개 문제를 접했을 가능성"이 있다 (Yeongeunn) → [[챗봇-평가-층위와-심판]].
- 재현성: 로컬 모델은 Modelfile·양자화·`num_ctx`까지 적어야 하고(lys0611), 외부 API는 모델 ID와 날짜가 필요하다. dldusgh318은 추출 모델명을 문서에 적지 않았다.

## 열린 질문

- 같은 질문·같은 근거로 로컬 7B와 외부 API를 블라인드 비교한 멤버가 없다(sunghyun이 시도했으나 질문이 달라졌다).
- 멀티턴·거절(negative rejection) 능력은 아무도 재지 않았다.
