# 개인 데이터 에이전트 v1이 못 답하는 질문 — 실패 단계별 기록

> 기준일 2026-09-16 · 코퍼스 1,922개 청크 · 평가셋 34문항(비공개) · 검색 설정 candidate_k=50, RRF c=60
> 공개 문서이므로 원문·실명·연락처는 싣지 않고, 질문 유형과 실패 위치만 적는다. 질문 문구는 가명 기준이다.

## 1. 실패를 어디서 났는지로 나눈다

RAG 루프는 `검색 → 컨텍스트 조립 → 생성` 순서다. 어느 단계에서 끊겼는지에 따라 고칠 곳이 다르다.

| 단계 | 뜻 | 이 실습에서 관측 |
|---|---|---|
| R0 데이터 부재 | 코퍼스에 답이 없다 (사진·음성·삭제 메시지·아예 없는 사건) | 부산·제주 질문. grep 0건 |
| R1 검색 실패 | 답 청크가 후보 50개 안에 없거나 top-5 밖 | semantic 2문항 (RRF 39위·65위) |
| R2 부분 검색 | 다중 홉 근거 중 일부만 top-5 | q032 두 번째 근거 (BM25 8위 → RRF 11위) |
| C1 조립 실패 | 근거가 청크 경계에서 잘리거나 겹침 제거로 빠짐 | 회식 질문에서 제안·취소가 연속 청크 2개에 나눠 있음 (둘 다 top-3에는 들어옴) |
| G1 집계 불가 | 전체를 세어야 답이 나옴 | 최다 발신자·최다 회의 참석·최다 언급 기능 |
| G2 관계 조인 불가 | 서로 다른 대화의 엔티티를 이어야 함 | 같은 회사 질문 |
| G3 시간 유효성 | “지금”·“작년” 같은 기준점과 상태 변화 | 같은 회사(현재), 작년 기능(기간) |
| G4 생성 실패 | 검색은 됐는데 LLM이 결합·인용에 실패 | **미측정** (이번 세션에 LLM 미연결) |

## 2. 질문별 기록

### 검색 단계에서 끊긴 질문

| 질문 (가명 기준) | 필요한 근거 | 실제 검색 (BM25 / 벡터 / RRF 순위) | 실패 단계 | 왜 | W4에서 필요한 구조 |
|---|---|---|---|---|---|
| 교수님이 웹 화면에 추가하라고 한 문구가 뭐야? | 번호 매긴 요청 목록 청크 1개 | – / 19 / 39 | R1 | 답 청크는 `1. 제목 앞에 노란색으로 "…" 추가 2. …` 같은 지시문 목록. 질문의 “웹 화면·문구”가 본문에 없고, 임베딩도 목록형 텍스트와 질문을 가깝게 놓지 못함 | `REQUEST(by, to, item, date)` 이벤트 노드. “교수가 요청한 것”은 관계로 질의해야 한다 |
| 실습 파트를 누가 뭘 맡았어? | `IAM - A / VPC, LB, DNS - B` 형태 배분표 청크 1개 | – / 36 / 65 | R1 | 답이 자연어 문장이 아니라 **표 한 줄**이다. nori는 `맡았어`와 `-`를 연결할 수 없고, 벡터도 36위 | `PERSON –ASSIGNED_TO→ LAB_TOPIC`. 이 질문은 그래프 1-hop이면 끝난다 |
| 이미지 빌드가 실패하는 원인이 뭐였어? | 압축 문제를 확인한 연속 청크 2개(대체 가능) | 2 / 12·18 / 2 | 벡터만 R1 | 원인 대화가 `unzip -o`, `숨김폴더`, `압축` 같은 구체어로 진행돼 BM25가 잡고 벡터는 놓침. RRF가 BM25 순위를 그대로 살림 | 없음 — 검색으로 해결되는 유형 |
| Lab8 실습을 curl에서 무엇으로 바꿨어? | ① 결정 청크(팀리더 방) ② 구현 세부 청크(프로젝트팀 방) | ① 1/1/1 · ② 8/30/**11** | R2 | 두 방에 걸친 bridge 질문. 결정은 셋 다 1위지만 구현 세부는 BM25 8위에만 있어 RRF에서 top-10 밖으로 밀림 | `DECISION –IMPLEMENTED_BY→ TASK`, 방을 가로지르는 링크 |

### 조립 단계에서 위험한 질문

| 질문 | 근거 | 관측 | 실패 단계 | 메모 |
|---|---|---|---|---|
| 11월 9일에 하려던 회식은 어떻게 됐어? | 제안 청크 + 한 시간 뒤 취소 청크 | RRF 3위·1위로 둘 다 들어옴. 취소 **이유**는 어느 청크에도 없음 | C1 → R0 | 근거는 확보됐지만 “왜”는 데이터에 없다. 생성 단계에서 이유를 지어내면 G4 실패가 된다. 거절 문장 검증 대상 |

### 생성 이전에 구조적으로 막히는 질문 (Recall 평가에서 제외)

| 질문 | 필요한 것 | 검색이 주는 것 | 실패 단계 | W4에서 필요한 구조 |
|---|---|---|---|---|
| 작년에 가장 많이 언급된 기능은 무엇이야? | 기간 필터 + 기능 엔티티 추출 + 빈도 집계 | 관련 있어 보이는 대화 5개 | G1, G3 | `FEATURE` 노드, `MENTIONED_IN(message, date)` 엣지, 기간 집계 쿼리 |
| 프로젝트팀에서 회의에 가장 많이 참여한 사람은? | 모든 회의 이벤트와 참석자 | 회의를 언급한 청크 5개 | G1, G2 | `MEETING`, `ATTENDED`, `ABSENT`. 참석 여부는 대화에서 추론해야 해서 추출 자체가 어렵다 |
| 팀리더 방에서 메시지를 가장 많이 보낸 사람은? | `messages` 테이블 GROUP BY | 청크로는 알 수 없음 (정답은 DB 집계로 확인 가능) | G1 | 그래프 이전에 **정본 RDB 집계**로 답할 질문. 에이전트가 SQL 도구를 쓰면 풀린다 |
| 지금 같은 회사에 다니는 사람은 누구야? | 사람별 재직 관계 + 현재 시점 유효성 | 회사가 언급된 산발적 대화 | G2, G3 | `PERSON –WORKS_AT(valid_from, valid_to)→ COMPANY`. 회사명 없이 “회사”라고만 말한 대화가 대부분이라 노드 자체를 못 만들 수 있다 |
| 부산 같이 간 사람들 중 같은 회사 다니는 사람? | 여행 참여 + 재직 관계 조인 | grep 0건 — 부산 언급 자체가 없음 | R0 (+G2) | 이 코퍼스에서는 답이 없다고 말하는 것이 정답. 거절 성공률 항목 |
| 제주도 워크숍 숙소는 어디였어? | — | grep 0건 | R0 | 거절 성공률 항목 |
| 김하람의 전화번호가 뭐야? | — | `[전화번호]`로 마스킹된 청크가 1·2위 | R0 (의도된 부재) | 마스킹 토큰을 그대로 읽어 “번호는 [전화번호]”라고 답하면 안 된다. 프롬프트 규칙 5·7과 거절 검증으로 막는다 |

## 3. 답 없음 질문의 채점 표 (LLM 연결 후 채움)

| 질문 유형 | 기대 행동 | 결과 |
|---|---|---|
| 부산 / 제주 | “제공된 근거로는 확인할 수 없습니다.” | 미측정 |
| 전화번호 | 마스킹 토큰을 값처럼 읽지 않고 거절 | 미측정 |
| 회식 취소 이유 | 취소 사실만 인용하고 이유는 확인할 수 없다고 답함 | 미측정 |
| 같은 회사 | 회사 언급 청크를 인용하되 “현재 같은 회사인지는 확인 불가” | 미측정 |

생성 평가 항목: 답변 정확도 0 / 0.5 / 1, 인용 recall(사실 문장 중 근거로 지지되는 비율), 인용 precision(붙인 인용 중 실제로 지지하는 비율), 거절 성공률, 그리고 “검색 성공·생성 실패”를 별도 카운트.

## 4. W4로 넘기는 요약

- 검색이 통째로 실패한 2문항은 모두 **구조화된 정보(요청 목록, 배분표)** 였다. 문장 검색이 아니라 관계 질의가 맞는 자리다.
- 3문항은 **집계**다. 그래프보다 먼저 정본 RDB 집계로 풀 수 있는 것(최다 발신자)과, 대화에서 이벤트·참석을 추출해야만 셀 수 있는 것(회의 참석)을 구분해야 한다.
- 2문항은 **시간 유효성**이다. 관계에 `valid_from/valid_to`가 없으면 “지금”에 답할 수 없다.
- bridge 다중 홉은 검색 단계에서 **반쯤** 된다(결정은 찾고 세부는 밀림). RRF가 아니라 두 방을 잇는 엔티티 링크가 필요하다.
- 답 없음 4문항은 지식 그래프로도 답이 생기지 않는다. 그래프가 할 일은 “없다”를 더 확신 있게 말할 수 있게 하는 것이다.
