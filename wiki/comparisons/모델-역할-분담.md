> "Gemini를 쓴다"만으로는 역할이 정해지지 않는다 — 생성용 Gemini와 Gemini Embedding은 다른 모델이다 (Yeongeunn). 한 문장에서 네 역할이 갈린다: 개체·개념 추출 / 관계·의사결정 추출 / 임베딩 / 생성. 역할마다 입출력·평가 기준·모델 종류가 다르고, 5주차 실측에서 멤버들이 역할마다 **다른 모델·다른 위치(로컬 vs 외부)**를 골랐다. "온톨로지는 모델 개수의 이름이 아니다. 의미와 규칙을 합의하는 층이다. 모델을 세 개 설치하는 것만으로 만들어지지 않는다" (Yeongeunn).

## 비교표 — 역할별

| 역할 | 입력 → 출력 | 평가 기준 | 모델 종류 | 멤버들의 선택 |
|---|---|---|---|---|
| 개체·개념 추출 (NER + 개체 연결) | 문장 → `재시도[Concept]`, `요청 ID[...]` + 타입 + 원문 위치 | 엄격 일치 P/R/F1 (경계 + 타입), micro vs macro | 규칙·사전 / CRF / BERT 미세조정 / 타입 입력형 LLM | 5주차 전원 LLM(OpenAI·Gemini); e0ng은 폴더·필드로 **결정적 추출**, LLM은 Topic만 → [[LLM-트리플-추출]] |
| 관계·의사결정 추출 | 문장(들) → `service:order –calls→ service:shipping`, 결정·이유·근거 구간 | gold-pair RE vs end-to-end, 의미 검수 | 전용 RE 모델 / LLM 구조화 출력 | 전원 LLM 구조화 출력 + 코드 검증 → [[폐쇄-스키마-설계]] |
| 임베딩 | 청크 → 벡터 | 자기 코퍼스의 Recall@k/nDCG, 인덱스 근사 오차와 분리 | SBERT 계열, bge-m3/KURE, e5, qwen3-embedding | **전원 로컬** → [[임베딩-모델-선택]] |
| 생성 | 질문 + 근거 → 답변 또는 관계 후보 JSON | 정답성·근거성·인용 지지·보류 표시 (사람), LLM judge | 로컬 7B / 외부 API | 로컬 셋, 외부 일곱 → [[생성-모델-선택]] |
| 심판 | 답변 + 기준 → 점수 | 사람과의 일치율, 편향 | LLM-as-judge, NLI 분류기 | e0ng(골든셋), kdyann(검토자) → [[챗봇-평가-층위와-심판]] |

- 층 구분 (Yeongeunn): ChatGPT = 제품 / GPT = 모델 / spaCy = 라이브러리 / Cohere Embed = 임베딩 모델 / LangChain = 연결 도구. 섞어 부르면 "어느 모델을 바꿔야 하나"를 못 정한다.
- 개체추출과 관계추출을 구분해야 한다. "'중복 주문'처럼 도메인 개념까지 추출하는 과제는 전통 NER보다 넓다 — 타입·라벨링 기준을 직접 정해야 한다."

## 파이프라인 3안 (Yeongeunn)

| 안 | 구성 | 강점 | 약점 |
|---|---|---|---|
| ① | LLM 추출 + 임베딩 + LLM 답변 | 변경이 쉽다 | 비용, **반복 실행 변동** |
| ② | 전용 NER + 관계추출기 + 임베딩 + 생성 | 단계별 검증 | **앞 단계 누락이 전파** |
| ③ | 규칙·사전 혼합 | 정형 표현에 명확 | 유지 비용 |

- 스터디의 5주차 실습은 전부 ①에 코드 검증을 더한 변형이고, e0ng만 ③(폴더·필드 규칙)과 ①(Topic LLM)의 혼합이다. ②는 아무도 안 했다.
- 모델 비교 5문항의 마지막: **"내 데이터의 최종 질문에도 그 점수가 의미 있는가."** 벤치마크 점수(KLUE·MTEB·MMLU)와 자기 코퍼스 점수는 다른 것이다.

## 갈리는 지점

- **로컬 vs 외부의 경계가 역할마다 다르다**: 임베딩은 개인 데이터 멤버 전원 로컬인데 추출은 전원 외부 API, 생성은 갈린다 → [[개인-데이터-가명화와-공개-범위]]. 이 경계를 누가 어떤 기준으로 정했는지 적은 멤버는 없다.
- **LLM에 맡기는 면적**: e0ng 최소(Topic만) / dldusgh318·heebindev·kdyann·Yeongeunn 전부(+검증). 면적이 작을수록 오류 면적도 작지만 폴더 구조가 온톨로지를 반영한 데이터에서만 가능하다 → [[LLM-트리플-추출]].
- **반복 실행 변동**: Yeongeunn은 첫 실행의 7개 출력을 재현하지 못했고(입력 구성이 바뀜), kdyann은 "매번 같은 모델 판정을 보장하지 않는다", do-dop은 temperature 0.2로 6회 반복을 안정화했다.

## 열린 질문

- 전용 NER/RE 모델(KLUE-NER·KLUE-RE 미세조정)과 LLM 추출을 같은 데이터에서 비교한 멤버가 없다. Yeongeunn 06이 평가셋과 지표를 정리해 두었다.
