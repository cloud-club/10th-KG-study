# 03. 임베딩 모델 비교

> 참고 자료:
> - MTEB / MMTEB 리더보드
> - BGE-M3, E5-Mistral, Qwen3-Embedding, ColPali / ViDoRe

## 한 줄 요약

리더보드는 출발점일 뿐이고, 임베딩 모델 결정은 자기 코퍼스의 MRR / NDCG로 내려야 한다.

## 핵심 개념

- retrieval 카테고리 점수만 볼 것. 종합 점수는 트레이드오프를 가린다.
- 차원 수·컨텍스트 길이·다국어 커버리지·라이선스·지시문 프리픽스 지원이 비교 축
- 2026년 현재 오픈 모델이 대부분 도메인에서 클로즈드 모델과 대등 → 선택은 운영·컴플라이언스 문제

## 상세 정리

### 역사 축

```
word2vec → SBERT → OpenAI ada-002 (2022, 사실상 기본값이던 시절)
  → E5 / BGE / GTE 오픈 모델
    → Matryoshka 표현 학습 (차원을 잘라 써도 성능 유지)
      → 지시문(instruction) 기반 임베딩 (E5-Mistral, Qwen3-Embedding)
        → 멀티모달 / 문서 이미지 검색 (ColPali, ViDoRe)
```

### 비교할 때 봐야 할 축

1. **retrieval 카테고리 점수만 볼 것** (종합 점수 아님)
   - 클러스터링을 잘하는 모델이 패시지 랭킹에서 처참할 수 있음
   - 종합 점수는 이 트레이드오프를 가림
2. 차원 수 → 저장·검색 비용에 직결
3. 컨텍스트 길이
4. 다국어 커버리지 (한국어 섞이면 MTEB 영어 표가 아니라 MMTEB/다국어 표)
5. 라이선스
6. 지시문 프리픽스 지원 여부

### ⭐ MTEB의 함정 (이 주제의 핵심 교훈)

> 법률 계약서 검색 시스템 사례: MTEB 상위 3개 모델이 자체 평가셋 200개 쿼리 기준으로는 **5위·7위·2위**.
> 실제로 이긴 모델은 당시 리더보드 **11위**였던 BGE-large-en-v1.5.

**리더보드는 출발점, 결정은 자기 코퍼스의 MRR / NDCG로.**

### 2026년 현재 상황

- 오픈 모델이 대부분 도메인에서 클로즈드 모델의 검색 품질과 대등
- 따라서 선택은 성능 문제라기보다 **운영·컴플라이언스 문제**
- BGE-M3처럼 dense / sparse / 멀티벡터를 한 모델에서 동시에 뽑는 선택지는 하이브리드 구현을 단순화
