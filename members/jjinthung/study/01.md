# W2~3. RAG란? — grep에서 벡터까지

## 0세대 — grep
> 문자열 매칭

### 장점
- 구현이 매우 간단함
- 별도의 검색 엔진이나 DB가 필요 없음
- 정확한 문자열 검색에 강함
- 결과가 예측 가능함
- 작은 규모의 데이터에서 빠르게 사용할 수 있음
- 추가적인 인프라 및 비용이 거의 없음

### 단점
- 표현이 다르면 검색하지 못함
- 의미적 유사성을 이해하지 못함
- 동의어 검색에 약함
- 오타 및 띄어쓰기 변화에 취약함
- 검색 결과의 관련도 순위를 제공하지 않음
- 데이터 규모가 커질수록 비효율적임


---

## 1세대 — 키워드 검색
> 역색인 / TF-IDF / BM25

### 장점
- 역색인을 통해 대규모 문서를 빠르게 검색할 수 있음
- 검색 결과의 관련도 순위를 제공할 수 있음
- 중요한 키워드에 높은 가중치를 줄 수 있음
- 정확한 키워드 검색에 강함
- 형태소 분석, n-gram, 동의어 사전 등을 활용할 수 있음
- 검색 결과의 근거를 비교적 명확하게 설명할 수 있음
- Elasticsearch 등 검증된 검색 인프라를 활용할 수 있음

### 단점
- 기본적으로 키워드 중심의 검색 방식임
- 표현이 다르지만 의미가 같은 문서를 찾는 데 한계가 있음
- 동의어 및 유사 표현 처리를 별도로 구성해야 함
- 한국어의 경우 형태소 분석 및 토크나이징 설정이 중요함
- 분석기 설정에 따라 검색 품질이 크게 달라질 수 있음
- 문맥이나 질문의 의미를 직접적으로 이해하지 못함
- 검색 품질 향상을 위해 튜닝이 필요함


---

## 2세대 — 벡터 검색
> Embedding / Cosine Similarity / ANN / HNSW

### 장점
- 의미적으로 유사한 문서를 검색할 수 있음
- 표현이 달라도 유사한 의미를 가진 문서를 찾을 수 있음
- 자연어 질문 검색에 강함
- 문맥과 의미를 어느 정도 반영할 수 있음
- 키워드가 정확히 일치하지 않아도 관련 문서를 찾을 수 있음
- HNSW 등의 ANN 인덱스를 통해 대규모 벡터 검색이 가능함

### 단점
- 임베딩 모델에 따라 검색 품질이 달라짐
- 임베딩 생성 비용이 발생함
- 벡터 저장을 위한 추가적인 저장 공간이 필요함
- 대규모 데이터에서 별도의 벡터 검색 인프라가 필요함
- 정확한 키워드, 숫자, ID, 코드 등의 검색에 약할 수 있음
- 검색 결과의 근거와 이유를 설명하기 어려움
- 모델 및 벡터 차원에 따라 검색 성능과 비용이 달라짐
- 청킹 방식에 따라 검색 품질이 크게 달라질 수 있음

# 세대별 비교

| 세대 | 검색 방식 | 핵심 | 장점 | 단점 |
|:---:|---|---|---|---|
| **0세대** | grep / 문자열 매칭 | 문자열이 같은가? | 단순함, 빠른 구현, 정확한 문자열 검색 | 의미 검색 불가, 순위 없음 |
| **1세대** | 역색인 / BM25 | 키워드가 얼마나 잘 일치하는가? | 빠른 검색, 관련도 순위, 키워드 검색에 강함 | 의미적 유사성에 한계 |
| **2세대** | Embedding / Vector Search | 의미적으로 얼마나 가까운가? | 의미 기반 검색, 자연어 검색에 강함 | 비용, 인프라, 정확한 키워드 검색에 한계 |
