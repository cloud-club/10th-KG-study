# control-plane 점검 주기 논의

1월에 API Server 관련으로 두 번 터져서 ([[INC-001-etcd-election-single-apiserver-stop]], [[INC-003-apiserver-etcd-tls-expiry]]) 정기 점검 항목을 정하자는 자리.

논의된 것

- 인증서 만료는 노드별로 확인해야 한다는 게 이번에 확인됐다. 한 노드만 보고 넘어가면 놓친다.
- 알람을 만료 60일/30일 전 두 번 보내기로. 한 번만 보내면 휴가랑 겹치면 끝.
- etcd 지표 중에 최소한 봐야 하는 것: WAL fsync 지연, 리더 변경 횟수, DB 크기.
- DB 크기는 NOSPACE 로 이어지면 리소스 변경 자체가 막히니까 우선순위 높음.
- LB 헬스체크 경로가 실제 준비 상태와 다를 수 있다는 얘기도 나왔다. 이건 별도로 확인하기로.

정하지 못한 것

- 점검 주기를 주 1회로 할지 격주로 할지. 일단 격주로 시작해보고 조정.
- 점검을 자동화할지 수동 체크리스트로 갈지. 자동화 얘기는 나왔지만 담당을 못 정했다.

내가 할 것

- 인증서 만료 확인 절차 문서화 → [[kubeadm-인증서-갱신-절차]] 로 완료
- etcd 지표 대시보드 패널 초안
