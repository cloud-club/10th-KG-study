# 검색·답변 평가 기준

## 참고자료

- [Pinecone의 검색 평가 지표 설명](https://www.pinecone.io/learn/offline-evaluation/) — 같은 검색 순위에서 Recall·MRR·nDCG가 무엇을 보는지 비교.
- [Stanford IR 평가 정의](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html) — precision과 recall의 정의.

## 검색과 답변을 따로 평가하는 이유

필요한 문서를 잘 찾았더라도 답변이 조건을 빠뜨릴 수 있다. 반대로 답변이 자연스러워도 검색 근거에 없는 내용을 덧붙였을 수 있다. 검색은 **필요한 근거를 찾았는지**, 생성은 **그 근거로 정확히 답했는지**를 평가한다.

| 단계 | 확인할 것 | 지표·방법 |
|---|---|---|
| 적재 | 청크 누락·중복 여부 | ID·내용 해시·건수 비교 |
| 검색 | 정답 근거의 회수 | Recall@5 |
| 생성 | 핵심 사실·조건·인용의 정확성 | 질문별 수작업 채점 |
| 시스템 | 실행 비용 | 검색/생성 지연, 토큰, 호출 수 |

## Recall@5

```text
Recall@5 = 상위 5개에서 찾은 정답 근거 수 / 전체 정답 근거 수
```

정답 근거가 3개이고 상위 5개에서 2개를 찾았다면 `2/3 ≈ 0.667`이다. 상위 5개 중 관련 문서 비율인 `2/5`는 Precision@5다. 질문별 Recall을 계산한 뒤 평균과 유형별 결과를 함께 볼 수 있다. [Stanford IR 평가 정의](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html)

정답 근거가 없는 질문은 Recall의 분모가 0이므로 따로 분류한다. 이런 질문은 근거 부족을 적절히 밝혔는지 평가한다. 여러 문서를 함께 읽어야 하는 질문은 필요한 근거를 모두 찾았는지도 확인한다.

## 정답셋 구성

질문마다 사람이 원문을 확인해 정답 근거와 핵심 사실을 지정한다. 검색 결과에 나온 문서만 정답으로 잡으면 검색이 놓친 근거를 평가할 수 없으므로 관련 원문도 함께 검토한다.

| 질문 유형 | 확인하려는 차이 |
|---|---|
| 정확한 용어·식별자 | API 이름이나 전문 용어 검색 |
| 다른 표현·동의어 | 단어가 달라도 관련 문서를 찾는지 |
| 조건·부정·예외 | 조건을 빠뜨리지 않는지 |
| 다중 홉 | 여러 문서의 근거를 함께 찾는지 |
| 문서에 없는 질문 | 근거 없는 답변을 피하는지 |

복제된 문서는 같은 근거로 묶고, 겹치는 청크도 중복 기준을 고정한다. 서로 다른 문서 버전의 상충하는 주장은 단순 중복으로 합치지 않는다. 튜닝에 사용한 질문과 최종 확인용 질문도 분리한다.

## 비교 조건

| 항목 | 설정 |
|---|---|
| 검색 방식 | BM25 / 벡터 / RRF |
| 입력 | 같은 문서 스냅샷·청크·질문 |
| 검색 평가 | 상위 5개, 동일 중복 제거 기준 |
| RRF 시작 설정 | 검색기별 후보 30개, c=60 |
| 생성 비교 | 같은 모델·프롬프트·근거 수·출력 예산 |

## 답변 채점

- 질문에 필요한 핵심 사실과 예외 조건을 포함했는가?
- 원문에 없는 숫자·조건·설계 이유를 덧붙이지 않았는가?
- 인용한 문서가 실제 주장을 뒷받침하는가?
- 근거 부족이나 문서 충돌을 적절히 표현했는가?

실패한 질문에 정답 근거를 직접 넣어 보는 oracle context 실험도 검색과 생성의 문제를 구분하는 데 도움이 된다. 정답 근거를 줬을 때만 맞으면 검색·청킹을, 그래도 틀리면 생성·프롬프트를 살펴본다.
