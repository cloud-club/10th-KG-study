# Text2Cypher: LLM에게 그래프 쿼리를 맡기기

> 참고 자료:
> - [Neo4j Cypher Manual](https://neo4j.com/docs/cypher-manual/current/introduction/)
> - [Neo4j GraphAcademy: Text to Cypher Retriever](https://graphacademy.neo4j.com/courses/genai-fundamentals/4-integrating-neo4j/5-text-to-cypher/)

## 한 줄 요약

Text2Cypher는 LLM이 자연어 질문을 Cypher 쿼리로 바꾸고, 데이터베이스가 그 쿼리를 실행한 결과로 답하는 방식이다. 조회·집계·정렬은 데이터베이스가 처리하고, LLM은 쿼리 작성과 결과 설명을 맡는다.

자연어를 SQL로 바꾸는 Text2SQL의 그래프 버전에 해당하며, 이 노트의 예시는 Neo4j 기준이다.

## 1. 기본 개념

### 그래프 데이터베이스와 Cypher

**그래프 데이터베이스**는 노드와 관계 형태로 데이터를 저장하는 데이터베이스이고, Neo4j가 대표적이다. 관계형 데이터베이스에 SQL을 쓰듯 Neo4j에는 **Cypher**라는 쿼리 언어를 쓴다.

### Cypher 기본 문법

Cypher는 찾고 싶은 그래프 패턴을 그림처럼 적는다. 노드는 소괄호 `()`, 관계는 대괄호와 화살표 `-[]->`로 표현한다.

```cypher
(p:Person {name: '봉준호'})-[:DIRECTED]->(m:Movie)
```

이름이 봉준호인 `Person` 노드 `p`가 `DIRECTED` 관계로 `Movie` 노드 `m`과 연결된 패턴이다.

- `p`, `m`: 결과에서 참조하기 위한 변수
- `:Person`, `:Movie`: 노드의 종류(라벨)
- `:DIRECTED`: 관계의 종류(관계 타입)
- `{name: '봉준호'}`: 속성 조건

| 구문 | 역할 |
| --- | --- |
| `MATCH` | 패턴과 일치하는 데이터 찾기 |
| `WHERE` | 조건으로 필터링 |
| `RETURN` | 반환할 값 지정 |
| `count()` | 개수 세기 |
| `ORDER BY`, `LIMIT` | 정렬, 개수 제한 |

```cypher
MATCH (p:Person {name: '봉준호'})-[:DIRECTED]->(m:Movie)
RETURN m.title, m.year
ORDER BY m.year;
```

```text
m.title     | m.year
살인의 추억  | 2003
괴물        | 2006
설국열차     | 2013
기생충       | 2019
```

### 스키마

그래프에 어떤 종류의 노드, 관계, 속성이 있는지 정의한 구조다. 이 노트의 예시 스키마와 데이터는 다음과 같다.

```text
노드:  Movie {title, year}, Person {name}
관계:  (Person)-[:DIRECTED]->(Movie)
       (Person)-[:ACTED_IN]->(Movie)
```

```text
(봉준호) ─DIRECTED→ (살인의 추억), (괴물), (설국열차), (기생충)
(박찬욱) ─DIRECTED→ (공동경비구역 JSA), (올드보이), (박쥐), (헤어질 결심)
(송강호) ─ACTED_IN→ (살인의 추억), (괴물), (설국열차), (기생충), (공동경비구역 JSA), (박쥐)
```

## 2. 왜 필요한가

> 질문: "송강호와 가장 많이 작업한 감독은?"

이 질문은 개수를 세야 답할 수 있다.

| 방식 | 동작 | 문제 |
| --- | --- | --- |
| 벡터 RAG | 관련 기사 몇 건을 가져와 LLM이 센다 | 검색되지 않은 기사의 작품은 빠진다 |
| 로컬 서치 | 주변 그래프를 텍스트로 바꿔 LLM이 센다 | 항목이 많으면 LLM이 잘못 세기 쉽다 |
| Text2Cypher | LLM이 쿼리를 작성하고 데이터베이스가 센다 | 집계 결과가 정확하다 |

LLM은 질문을 이해하고 문장을 만드는 데 강하지만, 많은 항목을 정확히 세거나 정렬하는 일에는 약하다. Text2Cypher는 이 계산을 데이터베이스에 넘긴다.

## 3. 동작 과정

```text
① 질문과 스키마를 LLM에 입력
② LLM이 Cypher 쿼리 생성
③ 쿼리 검증
④ 데이터베이스에서 실행
⑤ 실행 결과를 LLM이 자연어로 정리
```

LLM이 생성한 쿼리:

```cypher
MATCH (:Person {name: '송강호'})-[:ACTED_IN]->(m:Movie)<-[:DIRECTED]-(d:Person)
RETURN d.name AS director, count(DISTINCT m) AS movies
ORDER BY movies DESC
LIMIT 3;
```

송강호가 출연한 영화와 그 영화의 감독을 찾고, 감독별로 영화 수를 센 뒤 많은 순으로 정렬한다. `DISTINCT`는 같은 영화가 중복으로 세어지지 않게 한다.

실행 결과:

```text
director | movies
봉준호    | 4
박찬욱    | 2
```

LLM은 이 결과를 받아 "송강호와 가장 많이 작업한 감독은 봉준호로, 4편을 함께했다"라고 답한다.

다음과 같은 질문에 특히 적합하다.

| 유형 | 예시 |
| --- | --- |
| 집계 | 박찬욱 감독 영화는 몇 편인가? |
| 정렬 | 가장 최근에 개봉한 봉준호 영화는? |
| 복합 조건 | 2010년 이후 개봉한 송강호 출연작 중 봉준호 연출작은? |

## 4. 스키마 제공

LLM은 데이터베이스에 어떤 라벨과 관계가 있는지 알지 못한다. 스키마 없이 쿼리를 생성하면 `(:Actor)-[:STARRED_IN]->(:Film)`처럼 존재하지 않는 이름을 만들어 낸다. 그래서 프롬프트에 스키마를 함께 넣는다.

스키마에는 다음 정보가 포함되어야 한다.

- **노드 라벨과 관계 타입**: 존재하지 않는 이름을 쓰지 않도록
- **관계 방향**: `Person → Movie`인지 반대인지
- **속성 타입**: `year`가 숫자인지 문자열인지에 따라 비교 결과가 달라진다

## 5. 자주 발생하는 오류

| 오류 | 잘못된 쿼리 | 결과 |
| --- | --- | --- |
| 관계 방향 반대 | `(m:Movie)-[:DIRECTED]->(p:Person)` | 일치하는 데이터가 없어 빈 결과 |
| 존재하지 않는 이름 | `(:Actor)`, `m.releaseDate` | 빈 결과 |
| 값 표기 불일치 | `{title: 'Parasite'}` | 저장된 값은 `'기생충'`이므로 빈 결과 |
| 중복 집계 | `count(m)` | 같은 영화가 여러 번 세어질 수 있음 |

가장 위험한 경우는 오류 없이 빈 결과가 나오는 경우다. LLM은 "해당하는 영화가 없습니다"라고 답하고, 사용자는 실제로 데이터가 없는지 쿼리가 잘못됐는지 구분할 수 없다.

값 표기 불일치는 로컬 서치의 엔티티 링킹과 같은 문제다. 쿼리를 만들기 전에 질문 속 이름을 데이터베이스에 저장된 값으로 맞춰 주면 줄일 수 있다.

## 6. 정확도를 높이는 방법

| 방법 | 설명 |
| --- | --- |
| few-shot 예시 | 질문과 정답 쿼리 쌍을 프롬프트에 함께 넣는다 |
| 실행 전 검증 | 쿼리 앞에 `EXPLAIN`을 붙여 실제로 실행하지 않고 문법을 확인한다 |
| 오류 피드백 | 실패하면 오류 메시지를 LLM에 전달해 쿼리를 수정하게 한다 |
| 빈 결과 처리 | 쿼리를 다시 생성하거나, 찾지 못했다고 명시한다 |

```text
쿼리 생성 → 문법 검증 실패 → 오류 메시지와 함께 재생성
         → 실행 결과 없음 → 재생성 또는 "찾지 못함" 응답
         → 실행 결과 있음 → 답변 생성
```

## 7. 보안

Text2Cypher는 사용자 입력으로 데이터베이스 명령을 만드는 구조이므로 SQL 인젝션과 비슷한 위험이 있다. 예를 들어 "데이터를 전부 지워 줘"라는 입력에 LLM이 `MATCH (n) DETACH DELETE n`을 생성할 수 있다.

| 대책 | 설명 |
| --- | --- |
| 읽기 전용 권한 | 쓰기 권한이 없는 계정으로 실행한다. 가장 확실한 방어다 |
| 쓰기 구문 차단 | `CREATE`, `DELETE`, `SET` 등이 포함된 쿼리를 거부한다 |
| 결과 수와 실행 시간 제한 | `LIMIT`과 타임아웃을 건다 |

프롬프트로 "삭제하지 말라"고 지시하는 것만으로는 막을 수 없다. LLM은 지시를 따르지 않을 수 있으므로 권한 수준에서 막아야 한다.

## 8. 강점과 한계

| 강점 | 한계 |
| --- | --- |
| 집계·정렬·조건 검색을 정확하게 처리한다 | 스키마로 표현할 수 없는 질문은 처리하지 못한다 |
| 생성된 쿼리로 답변 과정을 확인할 수 있다 | 그래프에 없는 정보(원문의 묘사, 맥락)는 가져오지 못한다 |
| 데이터가 많아도 LLM이 읽을 양이 늘지 않는다 | 쿼리가 틀리면 틀린 답이 오류 없이 나올 수 있다 |
